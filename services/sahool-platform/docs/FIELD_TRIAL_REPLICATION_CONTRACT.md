# Field trial replication and result identity

This contract covers the paired trial endpoint, descriptive MET calculations,
and spatial plot/outcome helpers. It does not establish that a supplied trial
exists in the season registry or that measurements were collected independently
in the field.

## Paired analysis

`POST /api/v1/trials/analyze` accepts one treatment/control yield pair per field
block. `block_number` must be a positive integer, unique within the request.
Repeating a row is an input error, not an additional replication. Yields must be
finite and `confidence_level` must be finite and strictly between zero and one.
The same checks apply to direct calls to `analyze_paired_trial`.

Four independent blocks are this calculator's minimum operating policy. This
does not prove independence or statistical power. Subsamples and repeated dates
must be resolved at their actual experimental-unit level before calling the
paired calculator; assigning new IDs to copies does not create independence.

Ordinary results retain the paired t-test, signed difference and confidence
interval. JSON scalars are native, finite values. `t_statistic` is now nullable:

| `statistic_status` | Meaning | `t_statistic` |
| --- | --- | --- |
| `ok` | Nonzero estimated standard error | Finite signed number |
| `zero_variance_equal` | All block differences are zero | `0.0` |
| `zero_variance_difference` | All block differences are the same nonzero value | `null` |

For constant nonzero differences, `p_value=0` and the point interval are limiting
conventions, not ordinary uncertainty estimates. Both zero-variance states now return `inferential_valid=false`,
`requires_review=true`, and `is_significant=false`. The limiting p-value is
retained for compatibility, not an ordinary significance decision. Consumers
must display the review recommendation. This intentionally changes the earlier
nonzero-constant case whose `is_significant` was true. The frontend honors both
the statistic status and the machine-readable review flags.
A zero control mean now returns `percent_change=null` and
`percent_change_status=zero_control`; the absolute difference and ordinary
nondegenerate analysis remain available. Otherwise the percentage status is
`ok`. Clients must allow null rather than interpreting it as zero percent.

Boolean measurements are rejected before conversion. Descriptive block counts
must be positive integers. Finite inputs whose arithmetic exceeds the supported
range raise a controlled ValueError rather than producing a nonfinite decision.
Validation failures return HTTP 422, including nested nonfinite numerical inputs.
The trial route error boundary returns at most 50 bounded diagnostic entries
(type, location, message), omitting raw input and exception context entirely.

Paired analysis remains available without a trial ID as a stateless calculator.
It does not certify a stored research experiment or authorize automatic learning.

## Descriptive multi-environment trials

When a `replicate` is supplied, the normalized combination of genotype,
environment and replicate must be unique. A replicate number can legitimately
recur for another genotype/environment combination. Re-importing the same
identified observation is rejected.

Rows without a replicate ID remain permitted for descriptive summaries. Their
independence is unverified; the routine does not silently deduplicate equal
values or claim an inferential replication count. Its descriptive-only scope,
complete genotype/environment matrix requirement and disabled decision/model
promotion eligibility are unchanged.

## Spatial plans and outcome migration

A request containing `spatial_plan` must provide a nonblank trial ID. The shared
placeholder `unbound-trial` is no longer accepted. This checks a caller reference,
not its existence in a canonical database.

Each assignment contains a deterministic `layout_id`, covering trial identity,
seed, treatment order, layout geometry and generation parameters. Plot IDs also
bind the physical assignment to that layout. A changed field, seed or layout
requires new plot identities. Outcome records, including those generated by
`extract_plot_zonal_outcomes`, carry the corresponding `layout_id`.

`bind_plot_outcomes` requires exactly the supplied plot-ID set and matching layout
identities. It rejects stale outcomes and edits to a physical assignment that
retain its old ID. These content digests are not signatures: they do not prove
measurement origin, and without the original layout manifest they do not prove
that the caller supplied every plot from that layout.

Outcome measurements must be a nonempty dictionary of finite numeric values.
Boolean values and malformed or overflowing quantities raise a controlled
`ValueError`; finite numeric strings remain accepted for compatibility. This
validation establishes input consistency, not the origin of measured evidence.

Legacy assignments or outcomes without layout identity fail closed. Regenerate
assignments from the verified original layout and reconstruct/re-extract the
associated evidence. Do not attach a current layout ID to old measurements or
rename old outcome keys merely to pass validation.

## Legacy design and promotion helpers

The design helper recognizes Arabic `شاهد` and English `control`, rejects
duplicate/blank treatment labels and does not insert a second control. Three
blocks remain its minimum design policy; four matched pairs are required for a
promotion signal in its separate descriptive screening helper.

The screening helper requires treatment/control lists in corresponding block
order. It considers control variation through paired differences, requires a
positive benefit and positive finite MDE, and prevents promotion with unmatched
or insufficient pairs. Its variability rule is explicitly descriptive:
the standard deviation of paired differences must not exceed the absolute mean
difference. This dimensionless product rule is invariant to measurement-unit
conversion; it is not a significance test. The confidence ceiling remains
`medium`, and explicit field identity is outside this list-based helper.

Randomization verification checks complementary, valid treatment/control
positions as well as the existing checksum. Generation and checksum formats
remain compatible. The checksum detects inconsistent edits, not an authenticated
adversary who can recompute it.
