# حوكمة البيانات وحقوق المزارع — SAHOOL Data Governance

> **شرط مسبق قبل جمع أي بيانات من المستخدمين.** هذه ليست وثيقة قانونية
> شكلية، بل التزام أخلاقي وعملي تطلبه خارطة طريق FAO للزراعة الرقمية صراحة:
> "حماية حقوق المزارعين وسيادتهم على بياناتهم".

تتبع هذه الوثيقة سقالة الحوكمة متعددة المستويات (farmer-centric data rights،
عتبات الشفافية، الإشراف البشري السياقي، كفاءة الطاقة الحاسوبية) المتوافقة مع
مبادئ FAO ونداء روما لأخلاقيات الذكاء الاصطناعي.

---

## المبدأ ١: حقوق بيانات المزارع وسيادته (Farmer Data Sovereignty)

```
القاعدة:  المزارع يملك بياناته. المنصة وصيّة، لا مالكة.
```

- **الملكية:** كل بيانات المزرعة (تربة، حصاد، آبار) ملك المزارع/المستأجر.
  تُخزَّن في `tenants/<id>/` معزولة بـ RLS، لا تُشارك دون إذن صريح.
- **الموافقة المستنيرة:** قبل أي مساهمة في المعرفة المجتمعية، يوافق المزارع
  صراحةً على ما يُشارَك وما يبقى خاصاً.
- **حق السحب:** يحق للمزارع سحب بياناته أو حذفها في أي وقت.
- **إخفاء الهوية:** المعرفة المجتمعية المنشورة تُجرَّد من هوية المزرعة
  (الموقع الدقيق، الاسم) ما لم يأذن المالك.
- **لا استخراج:** SAHOOL لا تبيع بيانات المزارعين ولا تبني نموذج عمل
  استخراجياً عليها (تجنّب "data-extractive business models").

## المبدأ ٢: عتبات الشفافية (Explainability Thresholds)

```
القاعدة:  كل توصية تحمل "شهادة ميلاد" — لا صندوق أسود.
```

- كل توصية مصحوبة بسلسلة نسبها (provenance.py): المصدر، نسبة الخطأ، الثقة.
- درجة الجودة معروضة دائماً (HIGH/MEDIUM/LOW/BLOCKED) — لا إخفاء للضعف.
- "قيد المعايرة" تُعرض كما هي، لا تُقدَّم تقديرات كأنها حقائق.
- المعرفة المحلية تُنسب لمصدرها (المزارع/المجتمع) بوزنها المحافظ (≤0.15).

## المبدأ ٣: الإشراف البشري السياقي (Context-Appropriate Human Oversight)

```
القاعدة:  القرارات الحرجة تحتاج إنساناً في الحلقة، لا أتمتة عمياء.
```

- **الحاكمات الصارمة** (S3, S4, I3, L3) — خاصة PHI (سلامة المبيد) — تتطلب
  تأكيد خبير زراعي قبل أي توصية كيميائية. لا أتمتة كاملة هنا.
- **المعرفة المجتمعية** تمرّ بفرز ثلاثي (آلي → تحقّق متقاطع → مراجعة خبير)
  قبل النشر العام.
- **التوصيات عالية التأثير** (تغيير محصول، استثمار) تُعرض كخيارات مُفسَّرة
  للمزارع ليقرّر، لا كأوامر.
- النظام يقترح، الإنسان يقرّر. خاصة في السياق شحيح البيانات.

## المبدأ ٤: كفاءة الطاقة الحاسوبية (Compute-Energy Efficiency)

```
القاعدة:  أبسط أداة تكفي. لا تعقيد بلا قيمة مُثبتة.
```

- SQLite لا Kafka/Qdrant حتى تُثبت الحاجة (قرار معماري موثّق).
- لا نماذج عميقة (BiLSTM) قبل توفّر بيانات تبرّرها (سُلّم النماذج).
- مناسب للسياق اليمني: بنية خفيفة تعمل بموارد محدودة.
- يتجنّب البصمة الكربونية للحوسبة المفرطة — متّسق مع هدف الاستدامة.

---

## التطبيق العملي في المنصة

| المبدأ | التطبيق الفعلي في الكود |
|--------|--------------------------|
| سيادة البيانات | عزل `tenants/<id>/` + RLS + موافقة صريحة |
| الشفافية | `provenance.py` + درجة الجودة + "قيد المعايرة" |
| الإشراف البشري | الحاكمات تتطلب خبيراً + فرز المعرفة الثلاثي |
| كفاءة الحوسبة | SQLite + سُلّم النماذج + لا تعقيد مبكر |

## الفجوة المتبقية (للمستقبل)

- **القابلية للتشغيل البيني:** اتّباع معايير ITU/FAO (FG-AI4A) لتوحيد
  توقّع الإنتاج ومراقبة التربة — يجعل SAHOOL قابلة للدمج عالمياً.
- **التقييم الذاتي:** قياس SAHOOL دورياً ضد AI Governance Toolkit من FAO.

---

> **الخلاصة:** SAHOOL متوافقة مع مبادئ FAO الأربعة للحوكمة المسؤولة. هذه
> الوثيقة تُحسم **قبل** جمع بيانات المستخدمين، لا بعده — لأن الثقة تُبنى
> من اليوم الأول، ولا تُسترجع إن فُقدت.

## ملحق: تعدّد المستخدمين وقرار قاعدة البيانات (محدّث)

الواقع: ٨ مزارع الآن، متوقّع ٥٠ خلال الشهر الأول من الإطلاق.

القرار المعماري بالعتبات:
- **< ٥٠ مزرعة**: SQLite (lite_store) — كافٍ تماماً، أبسط تشغيلاً.
- **٥٠–٢٠٠**: ترحيل مُخطّط لـ PostgreSQL (الجداول مصمّمة متطابقة — تغيير اتصال).
- **٢٠٠+**: PostgreSQL + PgBouncer (statement_cache_size=0) + RLS كامل.

عزل البيانات (multi-tenant): كل جدول يحمل farmer_id/tenant.
على SQLite: عزل بالاستعلام. على PostgreSQL: Row-Level Security.

الفلسفة التحفيزية (data_completeness.py):
- بدل BLOCKED القاطع → رسائل تحفيزية + شريط اكتمال + قيمة كل حقل.
- إشعارات لاحقة عند اكتمال البيانات/وصول نتائج المعمل.
- الحدّ الثابت: التحفيز للتوصيات العامة؛ المبيدات (L3/PHI) تبقى محجوبة (سلامة).

## ملحق: وحدة المعايرة = المديرية (تصحيح المصطلح)

التسلسل الإداري الصحيح في اليمن:
  الجمهورية → المحافظة (governorate) → المديرية (district)

وحدة المعايرة في SAHOOL = **المديرية** (district)، لا "الإقليم".
السبب: المديرية أصغر من المحافظة، فمزارعها أكثر تشابهاً مناخياً
وتربةً — ما يجعل معايرة الإنتاجية أدقّ.

تصحيح المصطلح عبر الكود:
- region_id → district_id (في كل الجداول والدوال)
- regional/ → districts/
- "إقليم" → "مديرية" (في الوثائق والرسائل)

ملاحظة: "الإقليم" ليس تقسيماً إدارياً قائماً في اليمن — كان خطأ مصطلحياً صُحّح.

عتبة المعايرة تبقى: ٥ مزارع/مديرية (farms_required، قابل للتعديل).
التجميع الجغرافي الأدقّ (DBSCAN داخل المديرية) مؤجّل حتى الحاجة.
