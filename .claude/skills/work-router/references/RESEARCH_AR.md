# الدراسة المقارنة: بناء منظومة مهارات قابلة للنقل والتحقق
**التاريخ:** 19 أكتوبر 2026. **النطاق:** GitHub وGitLab وGitee وGitCode ومعيار Agent Skills وTemporal وLangGraph وOWASP.

## 1) القرار الهندسي

لا نحاول إنشاء وكيل واحد يحمل جميع القواعد دائماً. الخيار الأفضل هو **واجهة مشتركة صغيرة + مهارات مستقلة تُحمّل حسب الحاجة + ملفات دليل اختيارية + أدوات تحقق قراءة فقط**. وهذا يطابق نهج Agent Skills في إظهار الوصف أولاً ثم النص الكامل عند اختيار المهارة، ثم المراجع عند الحاجة. نستخدم عتبة LIGHT/CHECKPOINTED/COORDINATED حسب المخاطر وحجم العمل، وليس ساعة زمنية جامدة.

النتيجة: ثماني مهارات جديدة إلى جانب مرجعَي UWRP Portable 3.1 وAdaptive Test Accelerator 1.1، ولم يُعدّل أي منهما. جرى وضع كل مهارة في مجلد مستقل مع `SKILL.md` قابل للنقل، وتم إعداد Prompt بديل لا يحتاج واجهة Skills.

## 3) تسعة تحسينات بمردود عملي

1. **Skill Router:** يختار أقل عدد كافٍ من المهارات ويمنع التحميل الزائد وتكرار التعليمات.
2. **Intent→Proof:** يربط كل مطلب بمخرج واختبار أو شاهد أو مراجعة؛ يمنع الادعاء بالإنجاز بلا معيار.
3. **Evidence Research:** يدرج المصدر الأصلي ونسخته وتاريخه ومستوى الثقة؛ لا يعدّ نسخ المستودعات شواهد مستقلة.
4. **Failure Investigation:** يبدأ بالأعراض والفرضيات والفحص الفارق؛ يحفظ شاهداً يفشل قبل الإصلاح إن أمكن.
5. **Coordination:** مالك كتابة واحد لكل مورد، ومراجعة مستقلة، وتحويل ملكية بإيصال. الحجز الذري لا يحل محل fencing.
6. **Change Review:** مراجعة diff/الأثر الحقيقي ورأس الفرع والقاعدة والاختبارات، لا وصف PR فقط.
7. **Safe Delivery:** تصريح محدد، وتأكيد الحالة المتغيرة قبل الأفعال، والتحقق من أثر timeout قبل إعادة المحاولة.
8. **Skill Evaluator:** اختبارات trigger إيجابية وسلبية وسيناريوهات حقن وضغط، ومقارنة مع/بدون Skill.
9. **Structural Guard:** مُدقّق يعمل دون شبكة يكشف Frontmatter غير صالح، وروابط ملفات مفقودة، وتغير بصمات الأساس أو قوالب JSON معطوبة.

## 4) التكاليف والبدائل

- **الأعمال البسيطة:** اختيار LIGHT مع Prompt مباشر، دون إنشاء ملفات حالة كثيرة أو تقييم مهارات.
- **الأعمال الطويلة:** CHECKPOINTED مع ملفات صغيرة وإيصالات، ونسخ خارجي مصرح به، واختبار مرتبط بمفتاح صلاحية مناسب.
- **العمليات الحساسة أو الوكلاء المتوازيون:** COORDINATED، وحقائق حية، وحماية جهة الهدف، وموافقة عند اللزوم.
- **السرعة:** يمكن لتحليل أثر الاختبارات والتجزئة والتوازي المحدود تقليل الكلفة، لكن تحسينات الأداء **افتراضات يجب قياسها**. لا يجوز تعطيل بوابة إلزامية لإظهار تسريع مصطنع.

## 5) أحكام التحقق والاعتماد

**ما هو مثبت ضمن هذه الحزمة:** صيغة الملفات، قابلية قراءة JSON، فحص SHA للملفات، حفظ الحزم المرجعية الأصلية، الاختبارات البنيوية للوحدات والقواعد المحلية. **ما ليس مثبتاً:** تفعيل Skills تلقائياً على Codex/Claude/Kimi، دقة قرارات الوكيل في العالم الحقيقي، تحسن الزمن/الكلفة، قفل موزع حقيقي، تشغيل بوابات مشاريع المستخدم، صلاحية إنتاج أو نجاح رفع GitHub.

المسار المنهجي لقبول فعلي: baseline بلا Skills → تجربة بالمهارة على نفس المدخلات والسياق المتاح → مراجعة عمياء للنتائج → مقارنة صحة، وقت، كلفة، أخطاء تخطّي وحوادث أثر خارجي → Pilot على مشروع غير حساس → اعتماد على نطاق أوسع مع مالك وتاريخ مراجعة.

## 6) مصادر وسلسلة توثيق

السجل التفصيلي `SOURCE_REGISTER.json` يحدد URL والمصدر ودوره وحدود استخدامه. الروابط مؤشرات أصلية للبحث والتحقق، لا برامج قابلة للتشغيل، ولا تتضمن شيفرة طرف ثالث داخل هذه الحزمة. راجع أحدث إصدار لكل مصدر قبل اتخاذ إجراءات على مشروع حقيقي.
