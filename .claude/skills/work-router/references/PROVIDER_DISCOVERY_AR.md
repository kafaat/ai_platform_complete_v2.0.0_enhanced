# دليل اكتشاف المهارات بحسب الوكيل والمنصة — تحقق 2026-10-19

**هذا دليل اختياري.** لا تنفذ أوامر تثبيت تلقائياً، ولا تعتمد على اسم المنتج وحده. تأكد من إصدار الوكيل والصلاحيات وما إذا كانت الجلسة المحلية تشارك مخزناً دائماً مع الجلسة السحابية.

| المنتج/البيئة | اكتشاف المهارة الموثق | قيد / مرجع أصلي |
|---|---|---|
| Codex / OpenAI API | دليل SKILL.md قابل للتوزيع كحزمة مجلد أو ZIP لكل Skill مستقل | طريقة الرفع والاكتشاف تعتمد بيئة API/CLI، ليست هي نفسها تهيئة الحساب؛ https://developers.openai.com/api/docs/guides/tools-skills |
| Claude Code | مهارات المشروع أو المستخدم؛ يحدد الإصدار طريقة التفعيل | لا تفترض بقاء الملفات المحلية داخل حاوية Claude السحابية؛ تحقق في وثائق الإصدار المستخدم |
| Kimi Code CLI | مشروع `.kimi/skills/` أو `.agents/skills/`، مستخدم `~/.kimi/skills/` أو `~/.config/agents/skills/` بحسب أولوية الإصدار؛ يدعم `/skill:<name>` | أولوية المصادر وتصادم الأسماء مهمان؛ https://github.com/moonshotai/kimi-cli/blob/main/docs/en/customization/skills.md |
| OpenCode | `.opencode/skills/` و`.agents/skills/`، أو مجلدات التوافق مع Claude؛ أدوات الاختيار قد تحجب مهارات حسب السياسة | https://opencode.ai/docs/skills |
| GitLab Duo | مستوى مشروع: `.agents/skills/<name>/SKILL.md` أو `skills/<name>/`، ومستوى مستخدم لنسخ CLI المدعومة | التوفر يتأثر بالخطة وإصدار CLI، وتغيير Skill لا يُحدّث المحادثات القديمة تلقائياً؛ https://docs.gitlab.com/user/duo_agent_platform/customize/agent_skills/ |
| Gitee / GitCode | منصات استضافة وليست بالضرورة أدوات تحميل Skills؛ تتطلب موصل/CLI أو تزويد Prompt | Gitee CLI يوزع مهارات إلى `~/.agents/skills/`؛ https://gitee.com/oschina/gitee-cli/blob/main/README.md |
| أي وكيل محادثة آخر | انسخ `UNIVERSAL_WORK_START_AR.md` وأرفق مهارة واحدة ذات صلة | النص لا يتيح تخزيناً دائماً، قفلاً موزعاً، ولا صلاحيات جديدة |

## سياسة التوزيع

1. اختر Skill واحدة مناسبة، وتأكد أن اسمها لا يتعارض مع اسم مثبت من نفس المستوى أو بمستوى أولوية أعلى.
2. تأكد من سلامة البصمة والمرجع والترخيص قبل نقل المحتوى؛ لا تسمح بتشغيل سكربت داخل Skill غير مدققة.
3. اختبر حالة إيجابية وأخرى سلبية على إصدار الوكيل المستهدف، ودوّن السلوك على نحو منفصل عن نجاح فحص بنية ملفات Markdown.
4. لتغيير مهارة مشتركة، استخدم نسخة جديدة ووثّق الرجوع؛ لا تكتب فوق المرجع القديم قبل قبول النتائج.
5. لا تجعل `SKILL.md` يعلو على تعليمات صاحب المهمة أو سياسة المستودع أو حدود أدوات النظام.
