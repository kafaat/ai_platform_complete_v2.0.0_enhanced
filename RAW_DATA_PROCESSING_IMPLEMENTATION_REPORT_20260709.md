# Raw Data Processing Implementation Report — 2026-07-09

## Scope

This continuation adds a non-breaking raw raster processing path to `raster-service`.
The feature is intentionally a QA/provenance path for raw scenes before indicator computation.
It does **not** fabricate vegetation/agronomic indicators and does **not** mark raw QA as an
indicator layer.

## New API contract

`POST /raw/process`

Request model: `RawDataProcessRequest`

Key fields:

- `tenant_id`
- `field_id` optional
- `raster_url`
- `bands` optional 1-based raw band indices
- `normalize_reflectance` optional
- `include_tags` optional
- `max_pixels` bounded sampling limit

Response model: raw metadata + per-band stats + provenance:

- `schema = sahool.raw_raster_processing/1`
- source metadata: width, height, band count, CRS/SRID, bounds, resolution, driver
- `raw_bands`: min/max/mean/std/p02/p50/p98/valid/nodata per band
- `normalized_bands`: optional reflectance stats
- `provenance.fabricated_indicator = false`
- `provenance.indicator_computed = false`

## Safety behavior

- Uses existing `raster_security_context.require_service_token` in the router.
- Uses existing `safe_raster_source` via `raster_processing_runtime.make_processing_context`.
- Reads large rasters with bounded sampling controlled by `max_pixels`.
- Rejects out-of-range band indices with a 400-compatible `ValueError` path.
- Does not change existing `/process` or `/process/batch` behavior.
