# مرونة تحت الفشل + تأكيد قوّة الاختبارات

عالجتُ بندين من المراجعة قابلين للتنفيذ بصدق offline: **اختبار الفوضى (chaos)**
و**تأكيد أنّ الاختبارات تكشف المنطق لا السطور فقط (mutation)**.

## ١. وهم التغطية — فُحص ودُحض (للاختبارات الأساسيّة)
المراجعة شكّت أنّ اختبارات router/vegetation قد "تمرّ على السطور لا تكشف
المنطق". أجريتُ **mutation يدوي**: قلبتُ شروطاً منطقيّة وراقبتُ هل تفشل الاختبارات.

| الطفرة | النتيجة |
|--------|---------|
| router: قلب عتبة الافتراضي `==0`→`>0` | ✓ كُشفت (14→2) |
| router: قلب اختيار `max`→`min` | ✓ كُشفت (14→5) |
| router: قلب شرط `if sub_scores`→`if not` | ✓ كُشفت (14→10) |
| vegetation: قلب عتبة `ndvi>=0.72`→`<=` | ✓ كُشفت (crash) |
| vegetation: تغيير `score 95`→`50` | ✓ كُشفت |

**النتيجة**: اختبارات router/vegetation **قويّة منطقيّاً** — لا وهم تغطية فيها.
(الوهم الأوّل الظاهر كان زائفاً: سلسلة `confidence=0.78` غير موجودة حرفيّاً،
فلم تتغيّر — لا ضعف اختبار.)

## ٢. اختبارات الفوضى (chaos/failure injection) — جديدة
المراجعة: "circuit breaker مُختبَر منطقيّاً لا تحت انقطاع حقيقي". أضفتُ
`test_chaos_resilience.py` (7 سيناريوهات تحقن أعطالاً):
| السيناريو | يتحقّق |
|-----------|--------|
| انقطاع متتالٍ | القاطع يفتح → fail-fast (يحمي من retry storm) |
| تعافٍ بعد المهلة | half-open → closed عند النجاح |
| عاصفة 1000 طلب أثناء الانقطاع | رفض نظيف، لا انهيار |
| عزل الأعطال | انقطاع خدمة لا يُسقط البقيّة |
| تذبذب (flapping) | فشل نصف-مفتوح يعيد الفتح فوراً |
| فشل جزئي ثمّ تعافٍ | نجاح يصفّر العدّاد (لا فتح مبكّر) |
| فشل مكرّر بعد الفتح | ثبات الحالة (لا استثناء) |

## ما يحتاج جهازك (لم أزيّفه)
المراجعة اقترحت أدوات لا أملكها offline:
- `mutmut run` — mutation شامل آليّ (أجريتُ يدويّاً عيّنة تمثيليّة فقط)
- `radon cc`/`xenon` — التعقيد الدوري
- `vulture` — dead code
- `schemathesis` — fuzzing العقود (يحتاج خدمة حيّة)
- `pip-audit`/`trivy`/`grype` — ثغرات التبعيّات والحاويات
- `locust`/`k6`/`py-spy` — الأداء (p95/p99، تسرّب الذاكرة)
شغّلها وارفع النتائج. خاصّةً `mutmut` (يؤكّد ما فحصتُه يدويّاً على كامل الكود)
و`pip-audit` (CVEs في التبعيّات غير المباشرة: httpx/cryptography/pillow/numpy).

## ملاحظة صدق
- mutation **أجريتُه فعليّاً** (قلبتُ شروطاً، شغّلتُ، رصدتُ الفشل) — عيّنة
  تمثيليّة لا شاملة. `mutmut` على جهازك يغطّي الكلّ.
- chaos tests **تعمل فعليّاً** (7/7) لكنّها تحقن الفشل في منطق القاطع، لا في
  انقطاع شبكي/DB حقيقي (يحتاج toxiproxy + بنية حيّة).
- اكتشفتُ وأصلحتُ خطراً في أداتي: mutation test كان يعدّل router.py مؤقّتاً
  (تداخل توقيت). عزلتُه في مجلّد مؤقّت — الأصل لا يُمسّ.
- المراجعة محقّة: لا فجوة معماريّة قاتلة. المتبقّي طبقة تشغيليّة (load/chaos
  حقيقي/contract fuzzing) تحتاج بنيتك.
