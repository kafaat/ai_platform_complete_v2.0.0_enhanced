# اكتشاف حرج من تشغيلك الفعلي: خطأ tatweel في الموجّه

تشغيلك الفعلي للاختبارات كشف — بشكل غير مباشر — **خطأً خطيراً** في طبقة
التوجيه (router) كان سيعطّل النظام للمستخدم العربي. هذا بالضبط ما يبرّر
"verification-driven engineering".

## الخطأ
`router.py` يصنّف استعلامات المستخدم (NDVI؟ سعر؟ آفة؟) لتوجيهها للمهارة
الصحيحة. لكنّ الأنماط العربيّة كُتبت بـ **tatweel (ـ) بين كلّ حرفين**:
```
النمط:        سـعـر  (فيه tatweel ـ)
ما يكتبه المزارع: سعر   (عربي طبيعي)
```
**النتيجة**: 320 tatweel في الأنماط → كلّ استعلام عربي طبيعي **يفشل المطابقة**
→ يُصنَّف خطأً كـ"advisory عام" → يُوجَّه للمهارة الخاطئة.

## القياس الفعلي
| | قبل الإصلاح | بعد الإصلاح |
|--|------------|-------------|
| تصنيف عربي صحيح | **1/6** (NDVI الإنجليزي فقط) | **6/6** |

أمثلة كانت تفشل:
- "ما سعر القمح في السوق؟" → advisory (خطأ) → الآن market ✓
- "لدي آفة في الحقل" → advisory عام (خطأ) → الآن advisory/pest_id ✓
- "متى أسقي المحصول؟" → advisory (خطأ) → الآن crop_model/irrigation ✓

## الإصلاح
1. إزالة 320 tatweel من أنماط router.py (حرف زخرفي بلا معنى دلالي)
2. إضافة صيغ الفعل "أسقي/اسقي/سقي" لنمط الري (المزارع يستخدمها)

## لماذا هذا مهمّ جدّاً
- **المستخدم الأساسي عربي** (مزارع يمني) → الخطأ يعطّل النظام لجمهوره الرئيسي
- **صامت**: لا يرمي خطأً، فقط يوجّه خطأً → يصعب اكتشافه دون اختبار
- **لم تكشفه** أيّ مراجعة سابقة (قرأت البنية لا السلوك) — كشفه **تشغيلك الفعلي**
