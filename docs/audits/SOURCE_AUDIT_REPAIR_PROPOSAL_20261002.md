# متابعة مراجعة SAHOOL من المصدر: إصلاحات التفويض والسياسة والمعاملة

هذه حزمة إصلاحات محلية قابلة للمراجعة لخمسة بنود من التدقيق السابق: الجزء الخاص بالتربة من **F01**، و**F02 وF04 وF05 وF09**. لم تُدمج التغييرات، ولم تُدفع إلى GitHub، ولم يحدث نشر أو تغيير في Railway. بنود سجل الفجوات تبقى **open**؛ نجاح المقترح محليًا لا يغيّر حالة `main`.

**الأساس:** `f60f0635398963f0fb0442c60bb51d774687393d`، بتاريخ 2 أكتوبر 2026. **الفرع المحلي:** `codex/source-audit-fixes-20261002`. النتائج مستنبطة من المصدر التنفيذي والاختبارات. استُخدمت تعليمات المساهمة وسجل الدماغ لتنظيم التغيير فقط، لا لإثبات الفجوات.

## 2. عقد BFF للتربة

التنفيذ يعيد استعمال `require_permission` ومصفوفة RBAC وسجل رفض الصلاحيات القائمين في المنصة. لا يُستنبط الإذن من وجود JWT، ولا يتحول تسجيل router داخلي جديد تلقائيًا إلى واجهة متاحة للمستخدم.

البادئة الخارجية هي `/api/soil/`. الجدول التالي يسرد **12 تركيبًا من method/path**، لا 12 decorator جديدًا:

| Method | المسار بعد البادئة | الصلاحية |
| --- | --- | --- |
| GET | `health` | `settings:view` |
| GET | `healthz` | `settings:view` |
| GET | `readyz` | `settings:view` |
| GET | `v1/soil/readings/{field_id}` | `observation:view` |
| GET | `v1/fields/{field_id}/soil/observations` | `observation:view` |
| GET | `v1/fields/{field_id}/soil/profile` | `observation:view` |
| GET | `v1/fields/{field_id}/soil/profile/history` | `observation:view` |
| GET | `v1/fields/{field_id}/soil/closed-loop` | `observation:view` |
| POST | `v1/soil/ingest` | `observation:record` |
| POST | `v1/soil/observations` | `observation:record` |
| POST | `v1/fields/{field_id}/soil/evidence` | `observation:record` |
| POST | `v1/fields/{field_id}/soil/profile/rebuild` | `observation:record` |

المسار غير المنشور يُرفض بـ404، والفعل غير المسموح على مسار منشور يُرفض بـ405 مع `Allow`. تتلقى خدمة التربة `X-Tenant-Id` و`X-Actor-Id` من المستخدم الموثوق، وتوكن الخدمة من إعداد المنصة؛ تُحذف القيم التي يحاول العميل تمريرها بدلًا منها. ملكية الحقل وعزل المستأجر في خدمة التربة يبقيان شرطين مستقلين.

تثبت الاختبارات أن viewer لا يكتب، وأن worker وagronomist وowner المسموح لهم يمرّون، وأن المستخدم غير النشط وplatform_admin لا يحصلان على بيانات التربة عبر هذا المسار. فحص الصحة يبقى متاحًا لـplatform_admin. أُعيد اختبار رفض viewer أيضًا عبر تطبيق المنصة ووسيطه الفعلي، مع استبدال المصادقة فقط؛ لم يُشغّل startup أو JWT حي.

**أثر التوافق:** هذا تضييق مقصود للـproxy الذي كان يقبل مسارات عامة. مسارات قراءة الواجهة الحالية الخاصة بالتربة بقيت قابلة للاستعمال في الاختبار. لم يُعثر على استعمال لمسار BFF للتربة في مصدر تطبيق المحمول المفحوص. لا يثبت ذلك عدم وجود عميل خارجي أو سكربت خارج المستودع؛ يلزم مراجعة مستهلكي المسارات المستبعدة قبل نشر الحزمة. ولم تُصلح هنا بوابتَا edge وsegmentation اللتان وردتا ضمن F01 الأوسع.

## 3. سياسة خروج السؤال الخام في NL→SQL

مصدر القرار هو صف `tenant_ai_policies` الذي يقرأه `load_tenant_ai_policy_row` داخل `tenant_connection(user)`. يُستخدم `build_ai_policy_envelope` القائم لإنتاج القرار، وتُفرض القيود المعلنة للمزوّد والنموذج قبل إنشاء العميل الخارجي.

| الحالة | نتيجة المقترح | طلبات المزوّد |
| --- | --- | --- |
| العلم معطل | 404 دون قراءة السياسة | صفر |
| لا مفتاح عند تفعيل العلم | 503 دون قراءة السياسة | صفر |
| لا صف سياسة، أو `local_only`، أو وضع غير معروف | 403 | صفر |
| `redacted_external` | 403؛ المسار يرسل سؤالًا خامًا ولا يملك تنقيحًا مُثبتًا | صفر |
| `full_external` لكن `ai_generation_allowed` غائب أو False أو None أو نص أو رقم | 403 | صفر |
| تعذر إنشاء اتصال السياسة | 503 | صفر |
| تعذر قراءة الصف | 403؛ القارئ الحالي يعيد السياسة الأكثر تقييدًا | صفر |
| قوائم السماح غير سليمة أو تستبعد المزوّد/النموذج | 403 | صفر |
| `full_external` مع `ai_generation_allowed is True` وقيود متوافقة | طلب إلى العميل الاختباري، ثم SQL يخضع للتحقق القائم | واحد في حالة النجاح الاختبارية |

قائمتا `allowed_providers` و`allowed_models` غير الفارغتين تُفرضان. الغياب أو القائمة الفارغة لا يضيفان تقييدًا، وفق دلالة عقد السياسة الموجودة؛ القيمة غير القائمة تُرفض. يستعمل المقترح تطبيع أسماء المزوّدات المشترك، بما فيه `claude` ← `anthropic`.

استُبدل `Anthropic` بـ`AsyncAnthropic` ضمن `async with`، مع `max_retries=0` و`timeout=20.0`. حد الانتظار هنا إعداد I/O للعميل، **وليس إثباتًا لحد زمني شامل للطلب**. لم يُقَس كمون مزوّد حي. يثبت اختبار متزامن قائم على أحداث أن انتظار المزوّد يسمح لمهمة أخرى بالتقدم؛ لا يعتمد على مقارنة أداء زمنية هشة. قواعد SQL القائمة لم تُوسّع.

## 4. معاملة إدخال التربة وهوية إعادة الطلب

تُبنى نماذج الأدلة قبل بدء الحفظ، ثم يستعمل المعالج اتصالًا ومعاملة واحدة. يُضبط `app.current_tenant` محليًا داخل المعاملة، ويُؤخذ قفل advisory للحقل والمستأجر قبل كتابة الأدلة ومهمة الإسقاط. يستعمل الإسقاط والمؤشر الاتصال نفسه قبل commit.

أُضيف مساعدان يعملان داخل معاملة المستدعي، مع الحفاظ على المساعدين العامين اللذين ينشئان معاملتهما لمن يستعملهما خارج الإدخال. لم تُضف جداول أو هجرات، ولم يُتجاوز RLS، ولم تُعدّل دلالات تركيب ملف التربة.

| نقطة الفشل المحقونة | الضمان المقاس محليًا |
| --- | --- |
| ضبط سياق المستأجر | لا كتابة ملتزمة |
| الخاصية الثانية | لا بقاء للخاصية الأولى أو الصف التوافقي |
| إضافة مهمة الإسقاط | لا دليل أو مهمة جزئيان |
| حفظ snapshot | لا حفظ جزئي قبل الإسقاط |
| تحديث المؤشر الحالي | rollback لجميع الكتابات |
| إلغاء المهمة أثناء إضافة عمل الإسقاط | لا commit؛ rollback يشمل الكتابة السابقة |
| إعادة القراءة نفسها بمفتاحها | نفس IDs المحفوظة ونفس هوية الملف؛ لا صف توافقي إضافي |
| إعادة مفتاح مستخدم لحقل آخر | 409؛ لا تغيّر في الحالة |

كشف المصدر أن `soil_readings` يملك مفتاحًا أساسيًا مولدًا، ولا قيدًا طبيعيًا فريدًا يزيل تكرار القراءة. لذلك لا يكفي `ON CONFLICT DO NOTHING`. في المقترح لا يُضاف الصف التوافقي عند تكرار جميع الأدلة الموجودة، وتُقرأ IDs الفعلية بدل إرجاع IDs جديدة لم تدخل القاعدة.

**حدود التكرار:** الطلب الخالي من جميع خصائص القياس يحافظ على السلوك السابق وقد يضيف صفًا توافقيًا عند إعادته. لا تفرض الحزمة بصمة حمولة كاملة لكل idempotency key؛ اختلاف المحتوى مع المفتاح نفسه داخل الحقل يحتاج عقدًا إضافيًا واضحًا. تُمنع في هذه الحزمة إحالة المفتاح إلى حقل/خاصية مختلفين. اختبار إعادة الطلب ليس إثباتًا لكل صورة من صور التزامن.

**حدود المعاملة:** المحوّل الاختباري يمثّل start/commit/rollback وقيد التفرّد المعروف ويشغّل المعالج والمخزن ومركّب الملف الحقيقيين. لا ينفّذ PostgreSQL SQL، ولا يثبت عزل MVCC أو RLS أو ترتيب الأقفال تحت ضغط متزامن. طول المعاملة صار يشمل تركيب الملف؛ يلزم قياس زمنها والتنافس على الحقل ببيانات ممثلة قبل النشر.

تفصيل الإخفاقات الثمانية: ثلاثة تخص مصنوعات جرد إصدار API وبصمة أساس القياس التي تحتاج إعادة توليد بعد تغيير المصدر. ثلاثة أخرى نتجت من SOCKS proxy في البيئة دون `socksio`، وحالة OTLP نتجت من تعطيل SDK في تشغيل التدقيق؛ نجحت الأربع عند إزالة هذه الإعدادات من عملية الاختبار المحلية فقط. الحالة الخامسة التي تظهر على الأساس تخص فحص سجل تاريخي يحتاج commit غير موجود في نسخة Git المختصرة. لم يُعد الجناح الافتراضي كاملًا بعد هذا التشخيص، ولم تُحتسب البقية نجاحًا.


الاختبارات الجديدة تستعمل التنفيذ الحقيقي عند حدود HTTP والسياسة والحفظ، مع بدائل محددة للمزوّد والاتصال. تشمل حالات المنع والسماح، واستبدال الهوية المنتحلة، والتراجع عند الخطأ والإلغاء، وإعادة الطلب. لم يُرسل سؤال أو نص أو طلب صوت إلى خدمة خارجية، ولم تُستعمل قاعدة إنتاج.

**PostgreSQL الأصلي:** جرى إعداد مِسبار منفصل لقاعدة مؤقتة، لكن الخادم لم يبدأ. تتيح البيئة UID 0 وحده، وPostgreSQL يتطلب مستخدمًا غير الجذر. الحالة المسجلة `not_executed` و`server_started=false`. لا يُعد هذا فشلًا في شيفرة المنتج ولا نجاحًا لاختبار RLS. يُرفق `probe_soil_postgres.py` لتشغيله في بيئة اختبار عادية؛ يعتمد هجرات المصدر المختارة ولا يحل محل اختبار MANIFEST كامل وصورة الخدمة.

**بوابات العمل:** نجح `ruff check` و`ruff format --check` بإصدار CI المثبت 0.15.8 على ملفات التنفيذ الأربعة والاختبارات الثلاثة، ونجح `git diff --check`. لم تُنفذ إعادة التوليد بثلاث تمريرات، ولم يُنفذ preflight الكامل أو CI على هذه الحزمة. نجح `preflight --fast --no-fetch` بلا إخفاقات أو تخطٍّ، على 12 ملفًا مُدرجًا في الفهرس. هذا المستوى لا يشغّل الجناحين أو إعادة التوليد، وبعض فحوص رسائل الالتزامات لم تقرأ التعديلات المحلية لأنها لم تُلتزم بعد؛ لا يُعد جاهزية للدفع.

## 7. ما يلزم قبل تحويل المقترح إلى PR قابل للدفع

1. مراجعة تضييق عقد BFF ودلالة سياسة السؤال الخام، خصوصًا أثر الرفض على مستأجري `redacted_external`.
2. تشغيل اختبار C على PostgreSQL مع الهجرات الفعلية ودور لا يتجاوز RLS، وحالات التزامن والإلغاء وإعادة الطلب.
3. إعادة التوليد حسب بروتوكول المستودع، وإثبات ثبات ثلاث تمريرات، ثم تشغيل بوابات التغيير والجناح المطلوب على الشجرة النهائية. لا تُرفع budgets لتغطية التغيير.
4. اعتماد الحزمة في طلب مستقل عن #1122، ثم إعادة التحقق على `main` حينئذ. أي نشر له تحقق صورة وهوية ومستهلك وخطة رجوع منفصلان.

لا تستند توصية الاعتماد إلى عدد اختبارات أخضر وحده. معيارها أن المستخدم غير المخول لا يكتب، والسؤال غير المصرح له لا يغادر المستأجر، والقراءة الواحدة لا تُترك نصف محفوظة، وأن حدود البيئة غير المقيسة ظاهرة للمراجع.
