# إصلاح فشل حاويتَي Odoo وRAG

أصلحتُ الأسباب عالية الاحتمال. **تنبيه صدق**: لم أرَ رسالة الخطأ الكاملة، فقد
يكون هناك سبب إضافي — في النهاية أمر يكشف السبب الدقيق.

## ١. حاوية Odoo (sahool-odoo) — السبب الأرجح: نفاد الذاكرة
- **المشكلة**: `mem_limit: 384m` لخدمة Odoo 17.
- Odoo 17 يحتاج **~1GB على الأقلّ** عند البدء — 384م تسبّب **OOM kill**
  (الحاوية تُقتل فور بدئها → تظهر كـ"فشل").
- **الإصلاح**: رفعتُ الحدّ إلى `1536m` (مقارنةً: postgres 1g، qdrant 2g).
- لو جهازك محدود الذاكرة الكلّيّة، خفّض خدمات أخرى أو شغّل Odoo منفصلاً.

## ٢. حاوية RAG (sahool-local-ai-rag) — السبب الأرجح: المرآة الصينيّة
- إصلاح sentence-transformers السابق **سليم** (تأكّدت: محذوفة).
- السبب المتبقّي: الـDockerfile كان يستخدم **مرآة pip صينيّة (tsinghua)**
  افتراضيّاً، وهي **بطيئة/محجوبة من اليمن** → timeout أثناء تثبيت langchain
  (تبعيّات كثيرة) → exit code 1.

## ٣. الإصلاح الجذري الشامل (17 خدمة)
وجدتُ أنّ **17 خدمة** كلّها تستخدم المرآة الصينيّة افتراضيّاً — خطر منهجي
لنشر في اليمن. غيّرتُ الافتراضي في كلّها إلى **PyPI الرسمي**
(`https://pypi.org/simple`) الذي يعمل عالميّاً.
- المرآة الصينيّة ما زالت متاحة لمن يريدها عبر `--build-arg`.

## الأمر الصحيح للتشغيل
```powershell
docker compose -f docker-compose.v9.yml --env-file .env up -d --build
```

## لرؤية السبب الدقيق لو تكرّر الفشل (مهمّ)
الرسائل تُقطع. لرؤية الخطأ الكامل:

### لـRAG (فشل بناء):
```powershell
docker compose -f docker-compose.v9.yml build sahool-local-ai-rag --progress=plain --no-cache 2>&1 | Select-Object -Last 40
```

### لـOdoo (فشل تشغيل، ليس بناء):
```powershell
docker compose -f docker-compose.v9.yml logs sahool-odoo --tail 50
```
ابحث عن: `OOMKilled` (نفاد ذاكرة) أو `could not connect to database`
(مشكلة postgres) أو `CREATE DATABASE` (صلاحيّات).

## احتمالات أخرى لـOdoo (لو لم يكن OOM)
- **صلاحيّة قاعدة البيانات**: Odoo يحتاج مستخدم postgres بصلاحيّة CREATEDB.
  `sahool_user` هو POSTGRES_USER فيصبح superuser تلقائيّاً (لديه CREATEDB) —
  فالأرجح ليست المشكلة، لكن تحقّق من اللوق.
- **تعارض البورت 8069**: لو خدمة أخرى تستخدمه.
- **postgres لم يصبح healthy**: Odoo ينتظر `service_healthy` — لو postgres
  بطيء، قد ينتهي مهلة الانتظار.

## ملاحظة صدق
رفعُ ذاكرة Odoo وتبديل المرآة إصلاحان عالِيا الاحتمال ومؤكّدان بنيويّاً (وجدت
384م فعلاً، والمرآة الصينيّة فعلاً). **لكنّي لا أرى لوقك الفعلي** — لو استمرّ
الفشل، شغّل أوامر التشخيص أعلاه وأرسل آخر 40 سطراً، وسأحدّد السبب بلا تخمين.
لم أزعم أنّ الإصلاح مؤكّد 100% دون رؤية الخطأ.
