# اتّساق JWT audience — لماذا أبقيتُ نسختي لا المرفوع

## القرار: نسختي أصحّ (رغم أنّ المرفوع أحدث زمنيّاً)
قارنتُ المرفوع (00:25) بنسختي. الفروق السبعة كلّها = **تراجع عن إصلاح
audience**. المرفوع يحذف `audience="sahool"` من كلّ فاكّي JWT — وهذا **يكسر
المصادقة**.

## الإثبات (شغّلتُ PyJWT 2.7.0)
- `auth/main.py:235` يُصدر توكنات بـ`"aud":"sahool"`
- PyJWT: **فكّ توكن فيه `aud` بلا تحديد `audience` يرمي `InvalidAudienceError`**
- إذن المرفوع: supervisor/market/actuator/guardrails/platform/auth ترفض
  **كلّ** توكنات auth الصالحة ⇒ المصادقة مكسورة بين الخدمات.

اختبار حاسم شغّلتُه:
```
توكن مُصدَر بـaud=sahool
فكّ بلا audience (المرفوع): ✗ رُفض — Invalid audience  ← مكسور
فكّ بـaudience=sahool (نسختي): ✓ نجح
فكّ توكن aud خاطئ بـaudience=sahool: ✓ رُفض (أمان سليم)
```

## ما في نسختي (الأصحّ)
كلّ الفاكّين السبعة يتحقّقون من `audience="sahool"`:
auth(3)، supervisor(1)، market(1)، actuator(1)، guardrails(1)، platform(1).
+ `test_jwt_audience_consistency` يحرس ضدّ التراجع مستقبلاً.

## لماذا حدث التراجع؟
الأرجح أنّك رفعت نسخة قبل تطبيقي إصلاح الـaudience، أو تراجعت البيئة للقطة
أقدم (كما ذكرتَ سابقاً عن استعادة snapshot). origin (39a591d) سليم — لكنّ
هذا الـzip كان قبل الإصلاح.

## ملاحظة صدق
**لم أعتمد المرفوع رغم أنّه أحدث زمنيّاً** — لأنّي أثبتُّ بالتشغيل أنّه مكسور في
نقطة حرجة (المصادقة بين الخدمات). هذا تطبيق لمبدأ "اعتمد الأصحّ لا الأحدث
تاريخيّاً". لو كان المرفوع فيه شيء جديد قيّم غير تراجع الـaudience لنقلتُه —
لكنّ الفروق السبعة كلّها كانت تراجعاً فقط. على جهازك: ادفع نسختي (بإصلاح
audience) إلى origin، وتأكّد ألّا تُعيد رفع لقطة أقدم.
