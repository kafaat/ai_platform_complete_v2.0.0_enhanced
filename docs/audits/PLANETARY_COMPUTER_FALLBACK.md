# دمج Microsoft Planetary Computer كمصدر احتياطي

نفّذتُ دمج Microsoft Planetary Computer كمصدر احتياطي (fallback) لصور الأقمار
عبر العميل المرن نفسه — مرونة إضافيّة لقلب النظام.

## لماذا Planetary Computer؟
- STAC عامّ، **بحث مجهول بلا حساب** (مثل Element84 تماماً)
- نفس بنية STAC → نفس payload يعمل دون تعديل
- يحوي Sentinel-2/1، Landsat، DEM (تغطية متداخلة مع Element84)
- استضافة Microsoft Azure (مزوّد مختلف عن AWS — تنويع حقيقي للمخاطر)

## كيف يعمل (سلسلة المرونة الكاملة)
العميل المرن الآن يجرّب بالترتيب:
1. **cache طازج** (Redis مشترك → ذاكرة)
2. **Element84** (الأساس) بإعادة محاولة + backoff
3. **Planetary Computer** (احتياطي) — جديد: عند فشل الأساس كلّيّاً
4. **cache منتهٍ** (stale-if-error)
5. **فشل صادق** (لا cache + كلّ المصادر فشلت → يرفع، لا يخترع)

## السلوك (مُختبَر)
- أساس فشل + احتياطي نجح → يُقدّم من PC مع وسم `_source: fallback` + تحذير
- أساس نجح → **لا يلجأ للاحتياطي** (لا حمل زائد، لا تأخير)
- الكلّ فشل بلا cache → يرفع بصدق (لا اختراع صور)
- النتيجة من الاحتياطي تُخزَّن في cache المشترك (يستفيد منها الجميع)

## المراقبة
مقياس Prometheus جديد: `sahool_stac_fallback_served_total` — يكشف كم مرّة
لجأ النظام للاحتياطي (مؤشّر صحّة Element84).

## الضبط (.env)
- STAC_FALLBACK_ENABLED=true (افتراضي مفعّل)
- PLANETARY_COMPUTER_URL=https://planetarycomputer.microsoft.com/api/stac/v1

## ملاحظة على التنزيل (صدق فنّي)
- **البحث**: يعمل مباشرةً عبر PC (مجهول).
- **تنزيل الأصول**: بعض أصول PC تتطلّب توقيع SAS token (مجّاني) عند التنزيل.
  الـfallback هنا يضمن **إيجاد المشاهد** عند تعذّر Element84؛ تنزيل البكسلات
  من PC قد يحتاج توقيعاً إضافيّاً (خطوة تشغيل لاحقة على جهازك إن لزم).

## ملاحظة صدق

الاتّصال الفعلي بـPlanetary Computer يحتاج httpx + شبكة على جهازك. لم أدّعِ
اتّصالاً حيّاً — اختبرتُ المنطق والتوجيه.
