## الفجوات المثبتة والإصلاح

### 1. سياسة ميزانية غير صالحة تُقبل أو تُسقط القارئ

**المعرف:** `BRAIN-HOT-BUDGET-ACCEPTS-INVALID-POLICY-01`.

كان `_budget_at` يستعمل `int(max_bytes)`، فيقبل النصوص العددية والكسور والقيم
المنطقية، ويتعطل على Infinity. وكانت مفاتيح JSON المكررة تُحسم لآخر قيمة بصمت،
والنسخة أو المخطط المعلنان لا يُفحصان. خلو خريطة الميزانيات عند الطرفين كان يترك
`hot.md` بلا سقف. وأثبتت المراجعة المستقلة أن مسار JSON يحتوي surrogate منفردًا
مهربًا يسبب `UnicodeEncodeError` خارج حدود تشخيص السياسة.

أصبح الحد عدد JSON صحيحًا غير سالب، والمفاتيح فريدة، والبيانات الوصفية المعلنة
مطابقة للمخطط والنسخة المدعومين. تُفحص مسارات نسبية قانونية قابلة لترميز UTF-8،
ويجب أن يحمل كل دفتر ذي أرشيف سقفًا. تبقى البنية المختصرة القديمة `{ "budgets": ... }`
مدعومة لأدوات المستودع، ويظل حذف سقف قائم أو رفعه `BUDGET_RAISED`.

**المصدر والشاهد:** [`brain_append_only_guard.py`](../../scripts/ci/brain_append_only_guard.py)
(`_budget_at`, `check_budget`) و[`test_brain_append_only_guard.py`](../../tests_v9/test_brain_append_only_guard.py).

### 2. قياس رابط أو قائمة مجلد بوصفهما محتوى الدفتر

**المعرف:** `BRAIN-HOT-BUDGET-MEASURES-NONFILE-OBJECTS-01`.

ينجح `git show ref:path` للرابط الرمزي والمجلد أيضًا؛ كانت البايتات المقاسة في هذه
الحالات نص وجهة الرابط أو قائمة الشجرة. وكانت أخطاء القراءة تختلط بغياب السياسة،
ويطبع مسار العرض هدفًا غائبًا بحجم صفر.

يقرأ `_budget_blob_at` الآن مدخل الشجرة ووضعه ثم كائن blob المحدد. تُقبل الملفات
العادية فقط؛ وفشل القياس يحجب بتشخيص مستقل، ويظهر الهدف غير المقاس بهذه الصفة.
الاختبارات تشمل حدود UTF-8 وCRLF، وصفر بايت، ونسخة عمل مخالفة للكائن الملتزم.

### 3. الحارس خارج الفحوص المطلوبة للدمج

**المعرف:** `BRAIN-HOT-BUDGET-GUARD-RUNS-IN-A-NON-REQUIRED-CHECK-01`.

على الأساس المذكور كان تشغيل الحارس الوحيد في `no-report-only-change`، بينما
`required_status_checks_contract.json` لا يطلب هذا السياق. أُكد التطابق بقراءة Ruleset
`main-protection` رقم `20645828` الفعال: عشرون سياقًا، منها `Repository Structural Lint`،
ولا يحتوي `no-report-only-change`. هذا إثبات لغياب الإنفاذ المطلوب، وليس ادعاءً برصد
عملية دمج مخالفة بالفعل.

أثبت مستودع اصطناعي أن رفع السقف من 100 إلى 120، مع دفتر حجمه 15 بايتًا، يمر من
اختبار الحجم الحالي، بينما يرفضه فحص الأساس والرأس بـ`BUDGET_RAISED`. أضيف تشغيل
الحارس إلى الوظيفة المطلوبة القائمة، مع تاريخ كامل ومراجع حدث ثابتة واختبار عقد
للتوصيل. لم تتغير إعدادات GitHub أو قائمة السياقات المطلوبة. سُجل موضع الحجب الجديد
بمثاله المضاد وطفرة مسجلة وشاهد موجب في
[`blocking_surface_additions.json`](../architecture/blocking_surface_additions.json).

### 4. حل تعارض يخرق بادئة الأرشيف الصارمة

**المعرف:** `ARCHIVE-CONFLICT-RESOLVER-BREAKS-PARENT-PREFIX-01`.

إضافتان مستقلتان إلى ملف الأرشيف نفسه جعلتا أداة الحل تخرج بنجاح وتفهرس ناتج الضم،
ثم يرفضه الحارس الأصلي بـ`ARCHIVE_REWRITTEN`. لا يمكن ضم لاحقتين مختلفتين مع إبقاء
بايتات الطرفين بادئة واحدة.

تفحص الأداة الآن بايتات طرفي الفهرس الخام قبل كتابة أو فهرسة أي ملف في الدفعة.
التعارض غير القابل للحفظ يبقى للمراجعة بتشخيص `ARCHIVE_PREFIX_CONFLICT`. وفي إعادة
التأسيس يُفحص الوالد الفعلي الجديد، بحيث يبقى إعادة تطبيق الإلحاق الصحيح مقبولًا.
تثبت الاختبارات ثبات الفهرس وملفات الأرشيف والسجلات والملفات المولدة عند الرفض.

**المصدر والشاهد:** [`resolve_merge_conflicts.py`](../../scripts/ci/resolve_merge_conflicts.py)
و[`test_resolve_merge_conflicts.py`](../../tests_v9/test_resolve_merge_conflicts.py).

### 5. قارئ الأرشيف يخالف وضع الملف الذي يحفظه Git

**المعرف:** `ARCHIVE-READERS-DISAGREE-WITH-GIT-MODES-01`.

عند `core.filemode=false` كان أرشيف ملتزم بوضع `100644` يختفي من القارئ بعد
`chmod 0755` رغم أن Git يرى الشجرة نظيفة؛ والعكس قد يجعل ملفًا متعقبًا بوضع
`100755` يدخل القراءة خطأً. ومع `core.symlinks=false` قد يبدو الرابط المتعقب
ملفًا نصيًا عاديًا فيُحتسب أرشيفًا.

يستعين التصنيف المشترك بالفهرس و`git diff-files` لتحديد الوضع الفعلي الذي سيحفظه
Git. اختبارات في مستودعات مؤقتة تقارن القارئ مباشرة بنتيجة `git add` و`write-tree`،
وشاهد من حارس التأجيلات يثبت أن بت تنفيذ يتجاهله Git لا يخفي بندًا مؤرشفًا.
يبقى تعريف الأرشيف `100644` و`hot_*.md` مباشرة تحت مجلده دون توسيع.
ولا يتبع القارئ رابطًا رمزيًا في مسار مجلد الأرشيف إلى محتوى لا تمثله شجرة Git.
