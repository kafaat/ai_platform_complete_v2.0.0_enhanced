# بوّابة تفعيل التعلّم المدفوعة بتدفّق البيانات

## الفكرة (طلبك)
الخدمة التعلّميّة تبقى **خاملة** حتّى يتدفّق ما يكفي من البيانات الناضجة،
فتُفعَّل **تلقائيّاً** عند بلوغ العتبة. يحلّ التوتّر: لا تعلّم من فراغ، لكن
تفعيل فوري عند الجاهزيّة.

## ما كان موجوداً (معزولاً) وما رُبِط
سهول كان يملك القطع لكن **غير موصولة**:
- `is_outcome_ready_for_learning`: نضج التوصية الواحدة (زمنيّاً) ✓ موجود
- `assess_learning_readiness`: معايير الجاهزيّة (50+/قبول/نضج) ✓ موجود لكن يأخذ أرقاماً جاهزة
- نمط `capabilities` ("حاضرة خاملة حتى التزويد") ✓ لكن شرطه env فقط

**الجسر المفقود الذي بُني**: يقرأ تدفّق البيانات الفعلي → يحسب المعايير →
يقرّر الحالة → يُفعّل تلقائيّاً.

## ما بُني: core/learning_activation.py
أربع حالات: **خاملة → تتراكم → جاهزة → مُفعَّلة**
- `DataFlowSnapshot`: لقطة التدفّق (نتائج مكتملة/مقبولة/ناضجة) لكلّ مستأجر
- `evaluate_activation`: يقرّر الحالة من اللقطة + التقدّم % + ما ينقص
- `activation_summary`: لوحة حوكمة عبر المستأجرين

## السلوك المُتحقَّق
- 0 نتائج → **خاملة** (لا تعلّم من فراغ)
- 25 نتيجة → **تتراكم** (50%، ينقص 25)
- 60 نتيجة + قبول 77% → **جاهزة** (تفعيل تلقائي)
- 60 نتيجة لكن قبول 40% → **تتراكم** (الانحياز يمنع رغم العدد — العدد وحده لا يكفي)
- سيادة البيانات: 4 مستأجرين، 1 جاهز (كلّ مستقلّ)

## المبدأ المحفوظ
- **مدفوع بالبيانات لا بـenv**: العتبة شرط موضوعي (50+ نتيجة، قبول≥70%، نضج≥80%)
- **خاملة بصدق**: قبل العتبة تُعلن "تنتظر البيانات"، لا تتظاهر بتعلّم لم يبدأ
- **سيادة المستأجر**: تدفّق A لا يفعّل خدمة B
- **حتمي**: عدّ + عتبات صريحة، لا نموذج، لا اختراع
- **يحترم RBAC**: endpoint بـrequire_permission

## التحقّق

- متحقَّق وظيفيّاً عبر دورة الحياة الكاملة (خاملة→تتراكم→جاهزة)

## ملاحظة صدق
هذه **البوّابة** لا التعلّم نفسه. حين تُفتَح (عند تدفّق بيانات كافية)، يبدأ
المسار الفعلي (feedback_closure) عمله على بيانات حقيقيّة. بنيتُ الآليّة التي
تقرّر **متى** يبدأ التعلّم بأمان — وهي الحلقة المفقودة بين "البيانات تتدفّق"
و"التعلّم يعمل". لم أبنِ تعلّماً وهميّاً؛ بنيتُ شرط تفعيله الصادق.
