# SIM-GOLDEN: قبول الدليل وربطه بسياسة التحقق

`scripts/simulation/sim_golden.py` يقيس تنبؤات إنتاجية **مرشح واحد** على أحدث موسم
حصاد لكل محصول. حساب المقاييس متاح للتشخيص؛ أهلية الترقية تحتاج أيضاً سياسة مستقلة
ببصمة متوقعة من إعداد موثوق وتوقيع HMAC صالح. لا تنفذ الأداة ترقية نموذج أو معايرة
أو كتابة إلى قاعدة البيانات.

## مدخلات البيانات والترتيب الزمني

تظل صيغة البيانات كائناً يحتوي `samples`. يحمل كل صف معرّفات غير فارغة للعينة
والمحصول والموسم والمزرعة، وإنتاجية مرصودة ومتنَبّأ بها، ومصدر مشاهدة من
`combine_weighbridge` أو `certified_scale` أو `erp_verified`، وتوقيتَي التنبؤ والحصاد،
و`model_version` و`input_digest`. تبقى معرّفات المستأجر الخام ممنوعة.

- يجب أن يكون التنبؤ **قبل** الحصاد؛ التساوي مرفوض. التوقيت ذو منطقة زمنية إلزامي.
- تُحوَّل التواريخ إلى UTC. تُرتَّب المواسم بنطاق تواريخ حصادها، لا بنص معرّفها؛
  يمكن أن يكون الموسم `10` أحدث من `9`. تغيير الاسم وحده لا يغير مقاييس الاختبار.
- تقاطع نطاقَي حصاد أو تلامسهما يجعل الترتيب ملتبساً، فتُرفض المجموعة. لا تستخدم
  الأداة ترتيباً أبجدياً لحسم التعادل. تُسجَّل النطاقات الزمنية في الدليل للمراجعة.
- تُرفض نسخة بيانات تجمع أكثر من `model_version`. لتقييم مرشحين، جهّز مجموعة
  مستقلة وسياسة مستقلة لكل مرشح. لا تُجمَع تنبؤات مرشح ضعيف مع تنبؤات مرشح آخر.
- عند ثبات الإنتاجية المرصودة في الاختبار، يكون `r2: null` ويفشل شرط R². لا يحتوي
  الدليل JSON على `NaN` أو `Infinity`.

### هوية المزرعة في التصدير

`scripts/simulation/export_season_runs_for_golden.py` يقبل JSON مجهزاً من المتصل،
مصفوفة صفوف أو كائناً يحتوي `rows`. يشترط `farm_id` صريحاً غير فارغ ويصدّر اسماً
مستعاراً مشتقاً منه. لا يتحول `field_id` إلى `farm_id`: ثلاثة حقول في مزرعة واحدة
ليست ثلاث مزارع، والسجلات ذات هوية مزرعة مجهولة تُستبعد بالسبب `missing_farm`.

جدول `season_simulation_runs` المنشأ في
`migrations/v207_historical_season_simulation_bridge.sql` يحمل `field_id` ولا يحمل `farm_id`.
لذلك لا تكفي صفوف ذلك الدفتر الخام للتصديق. يجب أن يمد المتصل التصدير بهوية مزرعة
موثقة من ربط الحقول بالمزارع ضمن المستأجر المأذون. يوجد ربط `fields.farm_id` قابل
للخلو في المخطط؛ هذه الأداة **لا تنفذ إثراءً أو استعلام SQL**، ولا تفترض أن هوية
المزرعة متاحة لكل سجل. عدم توفر الهوية يبقي السجل مستبعداً.

## سياسة المشغّل

تُمرَّر السياسة منفصلةً عبر `validation_policy` أو `--policy`. وجود حقل بهذا الاسم
داخل مجموعة البيانات لا يمنحها سلطة. لا يوجد حقل `approved: true` يمنح القبول؛
أي حقل مجهول في السياسة أو قواعد المحاصيل أو حدود المقاييس يُرفض، بما في ذلك
الأسماء المكتوبة خطأً.

مثال **اصطناعي للتوضيح فقط**؛ العددان 18 و3 هنا اختيارا المثال، وليسا حدّي كفاية
علمية أو سياسة جاهزة للإنتاج:

```json
{
  "schema_version": 1,
  "policy_id": "synthetic-wheat-example-v1",
  "candidate_model_version": "wofost-7.2",
  "registered_at": "2025-03-01T00:00:00Z",
  "crops": {
    "wheat": {
      "holdout_season_id": "2025",
      "min_holdout_samples": 18,
      "min_holdout_farms": 3
    }
  }
}
```

القواعد المطلوبة:

| الحقل | المعنى الملزم |
|---|---|
| `schema_version` | العدد الصحيح 1 |
| `policy_id` | معرّف غير فارغ للسياسة |
| `candidate_model_version` | مطابق تماماً للنسخة الوحيدة في جميع الصفوف |
| `registered_at` | توقيت ذو منطقة زمنية، يسبق أول تنبؤ في موسم الاختبار لكل محصول |
| `crops` | تغطية مطابقة تماماً لمحاصيل البيانات بأسمائها ذات الأحرف الصغيرة |
| `holdout_season_id` | معرّف الموسم المتوقع؛ يجب أن يطابق أحدث موسم المستنتج من التواريخ |
| `min_holdout_samples` | حد صريح لعدد صفوف **موسم الاختبار نفسه** |
| `min_holdout_farms` | حد صريح لعدد المزارع المميزة **في موسم الاختبار نفسه** |

العددان صحيحان موجبان؛ القيم المنطقية والكسور والنصوص العددية مرفوضة، وعدد المزارع
المطلوب لا يتجاوز عدد العينات المطلوب. يحدد المشغّل الحدود وفق غرض التحقق وتصميم
العينة؛ الأداة لا تخترع حدوداً موحدة للاختبار. العينات والمزارع في المواسم الأقدم
لا تسد نقص موسم الاختبار.

`registered_at` **إقرار مسجّل في السياسة** يفحص البرنامج اتساقه الزمني، ويرفض أيّ طابع
(`registered_at` أو `prediction_at` أو `harvest_at`) لاحقٍ للحظة التقييم: ما لم يحدث بعدُ ليس مشاهدة.
ولتثبيت الدليل على مجموعة بيانات بعينها يمرّر المتحقّق `expected_dataset_sha256`؛ بدونه تُثبت البصمة
سلامةَ المجموعة الموقَّعة لا هويّتها. التوقيع
والبصمة لا يثبتان بصورة مستقلة أن السياسة سُجّلت بالفعل قبل الاطلاع على النتائج.
يجب أن تأتي هذه الثقة من عملية المشغّل وسجلها الخارجي.

يمكن إضافة `thresholds` اختياري إلى السياسة لتجاوز الحدود القائمة. المفاتيح
المقبولة فقط هي `max_mape_pct` و`max_nrmse_pct` و`max_abs_bias_pct` و`min_r2`
و`min_samples` و`min_farms` و`min_seasons`. الحدود الافتراضية الحالية هي، بالترتيب:
20، 25، 10، 0.50، 30، 3، 2. العدادات الثلاثة الأخيرة تخص جميع صفوف المحصول وتبقى
فحوصاً منفصلة عن حدود موسم الاختبار. لتثبيت السياسة عبر إصدارات الأداة، اكتب كل
الحدود المطلوبة صراحةً في السياسة؛ القيم غير المذكورة تأتي من نسخة الكود المشغلة.
كل قيمة عددية يجب أن تكون منتهية وبنوعها الصحيح. لا تقبل الأداة `thresholds` داخل
البيانات عند تمرير سياسة مستقلة؛ تجاوزات البيانات مقصورة على التشغيل التشخيصي.

## البصمة المتوقعة وحدود الثقة

بصمة السياسة SHA-256 محسوبة على **JSON مقنن، لا على بايتات الملف الخام**:

```python
json.dumps(
    policy,
    sort_keys=True,
    separators=(",", ":"),
    ensure_ascii=False,
    allow_nan=False,
).encode("utf-8")
```

لإعادة حساب بصمة ملف سبق اختيار مصدره ومراجعته:

```bash
python3 - /protected/golden-policy.json <<'PY'
import hashlib
import json
import sys
from pathlib import Path

policy = json.loads(Path(sys.argv[1]).read_text(encoding="utf-8"))
body = json.dumps(policy, sort_keys=True, separators=(",", ":"),
                  ensure_ascii=False, allow_nan=False).encode("utf-8")
print(hashlib.sha256(body).hexdigest())
PY
```

حساب البصمة لا يمنح السياسة الثقة. يجب توفير القيمة المتوقعة من إعداد يملكه المشغّل
ومنفصل عن البيانات وملف السياسة الوارد؛ لا تستخرج القيمة المتوقعة تلقائياً من
مدخل غير موثوق ثم تعد مطابقته موافقة.

يشغّل workflow `SIM GOLDEN Certification` الأداة في بيئة `staging`، بملف بيانات
وملف سياسة من المسارين اللذين يحددهما التشغيل. يأخذ مفتاح التوقيع من السر
`SIM_GOLDEN_EVIDENCE_KEY` والبصمة المتوقعة من المتغير
`SIM_GOLDEN_POLICY_SHA256` الذي يجب أن يقيّد المشغّل سلطة تغييره. إعداد هذا المتغير
وحمايته مسؤولية المشغّل؛ سياق `vars` قد يأخذ القيمة من مستوى المؤسسة أو المستودع
أو البيئة، وذكر `staging` وحده لا يثبت حمايتها. هذه الرقعة والمراجعة المحلية لا
تتحققان من إعدادات الحماية أو المراجعين أو المتغيرات في البيئة المنشورة. عدم ضبطه
يبقي النتيجة غير مؤهلة، فلا يمر `--require-promotion-eligible`. تعديل workflow
وحده لا ينشئ المتغير أو سياسة حقيقية أو مفتاحاً.

```bash
python3 scripts/simulation/sim_golden.py /protected/golden-dataset.json \
  --policy /protected/golden-policy.json \
  --require-promotion-eligible
```

يمكن تمرير البصمة الموثوقة صراحةً بـ`--policy-sha256` بدلاً من متغير البيئة. لا
يُمرَّر مفتاح التوقيع في سطر الأوامر. تظل الأداة تقبل تشغيل البيانات وحدها للتشخيص.

## قراءة الدليل والتحقق منه

صيغة الدليل الجديدة `schema_version: 2` تسجّل المرشح، وبصمة البيانات، والسياسة
الكاملة وبصمتها، والحدود الفعلية، وعدد عينات ومزارع الاختبار، والفحوص والنطاقات
الزمنية. يشمل توقيع HMAC هذه الحقول جميعاً.

| الحالة | النتيجة |
|---|---|
| فشل أي معيار محسوب | `status: rejected`، غير مؤهل |
| نجاح المعايير دون سياسة أو دون بصمة موثوقة | `status: diagnostic`، غير مؤهل حتى مع توقيع |
| نجاح المعايير والسياسة المثبتة دون مفتاح صالح | `status: verified`، غير مؤهل |
| نجاح المعايير والسياسة المثبتة وتوقيع صالح | `eligible_for_promotion: true` لهذا المرشح وهذه السياسة |

يعني `criteria_passed` نجاح الفحوص التي أُجريت؛ لا يعوض السياسة المفقودة. على أي
مستهلك قرار أن يفحص الدليل مقابل **مرشحه وسياسة المشغّل المتوقعة**، لا أن يثق
بعَلَم الأهلية وحده:

```python
verify_signed_evidence(
    evidence,
    signing_key,
    expected_model_version=selected_candidate,
    expected_policy_sha256=trusted_policy_digest,
)
```

غياب أي توقع أو اختلافه يرفض الدليل. أدلة الصيغة القديمة 1 لا تُقبل للترقية بمجرد
سلامة توقيعها؛ يجب إعادة تقييم البيانات تحت السياسة الجديدة. التوقيع بلا سياسة
لم يعد يرفع نتيجة تشخيصية إلى دليل أهلية.

`model_version` هوية **معلنة**، وليس برهاناً على ثبات ملف النموذج أو أوزانه.
كذلك لا تثبت أعداد الصفوف والمزارع استقلال العينات أو سلامة مصادر المشاهدات أو
عمومية الدقة. يلزم تصميم تحقق ومصدر بيانات موثوقان خارج هذه الأداة. الشواهد
الاصطناعية في الاختبارات تثبت سلوك القبول والرفض البرمجي، ولا تثبت أداءً حقلياً.

## التحقق المحلي المحدد

```bash
python3 -m pytest tests_v9/test_sim_golden.py \
  tests_v9/test_export_season_runs_for_golden.py
```

تشمل الاختبارات إعادة تسمية المواسم، والتعادل والتقاطع الزمني، وخلط المرشحين،
ونقص عينات ومزارع الاختبار، وأنواع السياسة وقيمها، وتعديل السياسة أو البصمة،
وتوقعات المتحقق والتوقيع، وJSON المنتهي، ورفض الحقول ذات المزرعة المجهولة.
هذا تحقق محدد لا يحل محل بوابات المستودع أو دليله الحقلي.
