## المطلوب إرجاعه

أعد حزمة `v25-ai-acceptance.zip` تضم `summary.md` و`results.json` وأدلة كل اختبار.
لكل نتيجة: وقت UTC، معرّف الاختبار، نسخة المصدر، digest الصورة، الأمر المنفّذ بعد
تنقيح الأسرار، رمز الخروج/HTTP، الزمن، والحكم PASS / FAIL / BLOCKED مع السبب.
التشخيص قبل أي نشر للقراءة فقط. لا تُرسل رموز الدخول أو كلمات المرور أو ملفات `.env`
أو `docker inspect` الكامل. استخدم الاعتمادات المتاحة للوكيل محليًا دون إظهارها.
المخرجات المحجوبة بالأذونات أو البيانات الناقصة تُسجّل BLOCKED، وليست نجاحًا.

  غياب revision يبقى «غير مثبت»؛ لا تستنتجه من اسم image tag.
- قارن SHA-256 لملفات المصدر المعدّلة داخل الصورة بالملفات المقابلة في هذا الفرع؛
  مرّر سكربتات الفحص عبر stdin دون نسخ ملفات إلى الحاويات.
- الخدمات: frontend، ai-agronomist، platform، raster-service، vegetation-analysis،
  field-segmentation، sam2-inference، qdrant-seed، ollama، rag-retrieval،
  guardrails-engine، decision-service، edge-inference.
- سجّل HTTP وجسم `/healthz` و`/readyz` من داخل شبكة Compose ومن المسار الذي يستهلكه

## 2. SAM2 وGPU — تشخيص مستقل عن وجود الأوزان

المصدر الحالي يحدد PyTorch 2.7.0 / CUDA 12.8 بالفعل في Dockerfile وGPU override؛
صورة تُبلغ 2.5.1 تحتاج مطابقة build args وهوية الصورة أولًا.
كان `.env.example` يفرض صورة 2.5.1 / CUDA 12.4 رغم ذلك، ويحدد عنوان SAM2 بمنفذ
8000 بلا `/v1/predict`. أُصلحت القيمتان في هذا الفرع؛ تحقّق من بقاء النسخة القديمة
في ملف البيئة المحلي، لأنها تتقدم على افتراضات Compose عند البناء.

شغّل داخل **حاوية SAM2**، وليس Python المضيف:

```python
import json
import torch
info = {"torch": torch.__version__, "cuda": torch.version.cuda,
        "available": torch.cuda.is_available(), "arches": torch.cuda.get_arch_list()}
if info["available"]:
    info["device"] = torch.cuda.get_device_name(0)
    info["capability"] = list(torch.cuda.get_device_capability(0))
    try:
        a = torch.ones((16, 16), device="cuda")
        value = (a @ a).sum().item()
        torch.cuda.synchronize()
        info["kernel_ok"] = value == 4096
    except Exception as exc:
        info["kernel_ok"] = False
        info["kernel_error"] = str(exc)
print(json.dumps(info))
```

- سجّل وجود checkpoint وحجمه وبصمته ومطابقة البصمة المعتمدة. لا تولّد بصمة اعتماد
  لنموذج مجهول المصدر لمجرد تمرير الحارس؛ البصمة المحسوبة دليل مطابقة لا دليل ثقة.
- أعد بناء SAM2 من المصدر المثبت إن كانت الصورة قديمة، ثم أعد اختبار CUDA.
- بعد توفير checkpoint المعتمد: اختبار `/v1/predict` بصورة حقل معروفة ومحددة مسبقًا؛
  سجّل زمن الاستدلال، صلاحية هندسة EPSG:4326 وحدودها داخل نطاق الصورة.
- عند غياب النموذج: SAM2 `/readyz` يجب أن يرد 503، وfield-segmentation يعلن
  `model_ready=false` وauto/hybrid غير جاهزين؛ manual يبقى متاحًا.

## 3. Ollama وseed

- أرجع `/api/version`، أسماء/digests النماذج، و`ollama ps` قبل وبعد الإحماء مع
  CONTEXT / PROCESSOR / SIZE. سجّل قيم KEEP_ALIVE وCONTEXT_LENGTH المسموح بعرضها فقط.
- افتح سجل ai-agronomist بعد إعادة بنائه: lifespan يحمّل النموذج المحلي المفعّل
  بطلب فارغ بميزانية 180 ثانية، ولا يسحب نموذجًا غير موجود.
- `generation_startup=completed` إيصال إحماء عند الإقلاع؛ ليس ضمانًا ببقاء النموذج
  إلى الأبد. التوليد التفاعلي يحتفظ بمهلته، وإعداد خمول البيئة قد يتجاوز مثال 30m.
- قِس طلبًا باردًا واحدًا إن كان النموذج غير محمل أصلًا، ثم خمس طلبات دافئة، ثم طلبًا
  بعد الخمول الطبيعي. لا تُفرغ نموذجًا يخدم مستخدمين لمجرد الاختبار.
- سجّل `load_duration` و`total_duration` وذاكرة GPU عند توفرها؛ ميّز تحميل النموذج
  عن الوقت المستغرق في generation. اختبر نموذج التضمين بصورة مستقلة.
- بعد نجاح التضمين، أعد تشغيل seed وفق سياسة البذر القائمة وسجّل exit code وعدد
  الوثائق قبل/بعد. الإعادة يجب أن تحفظ الهوية الحتمية ولا تضاعف النقاط.
- الإصلاح يعيد محاولة أخطاء النقل و429/5xx ثلاث مرات بميزانية 180 ثانية لكل طلب؛
  401/403 وفشل بنية المتجه لا يعادان. أي فشل تضمين يمنع بدء الكتابة إلى Qdrant.
- لا تغيّر tenant الحجر ولا provenance ولا أهلية الوصفات من أجل نجاح الاختبار.

## 4. المعرفة وRAG

- أرجع جردًا مجمعًا لكل tenant/provenance status/prescriptive eligibility؛ لا ترسل
  نصوص مستأجرين آخرين. قارِن schema المتجه وهوية نموذج التضمين مع المستعلم.
- `canonical_payload_parity=false` في الكود إعلان نقص دليل جرد شامل؛ لا يُحوَّل إلى
  true لمجرد أن Qdrant أخضر أو أن البعد يساوي 768.
- جهّز قائمة المصادر المعتمدة للمستأجر التجريبي: المصدر، الإصدار، مقتطفات محددة،
  تاريخ النفاذ، وبصمات المحتوى. إن لم تتوفر المصادر فهذه المهمة BLOCKED.
- أدخل المحتوى المعتمد عبر `/v1/ingest` وعقد provenance الموجود، ثم اختبر البحث
  للمستأجر نفسه ولآخر. سجّل chunk IDs وترتيبها ومراجع المصادر ورفض العبور بينهما.
- اختبر `/api/rag/search` عبر frontend برمز صالح، وبرمز غائب، وبترويسة tenant مزورة.
  المطلوب وصول الطلب الموثق إلى RAG بالهوية المشتقة من المصادقة.

## 5. الدردشة والتحقق

يلزم حساب مستخدم تجريبي وحقل ينتمي إليه وله canonical products مؤهلة فعلاً.
الطلب العام بلا حقل أو حقل بلا قياسات لا يثبت نجاح مسار الحقائق.

- نفّذ `/api/ai-agronomist/chat` بسؤال عن قياسات الحقل وبـ`field_id` معروف.
- عند إخراج JSON صالح: تتولى المنصة إعادة قراءة الحالة بعد generation، ثم تطابق
  `evidence_fingerprint` والحقائق وتعيد صياغة الجواب من القيم المملوكة للخدمة.
  يجب أن يظهر `mode=validated_field_facts` و`generation_status=validated_structured_facts`
  وإيصال `persisted=true` و`advisory_validation.status=verified`.
- هذه أهلية **حقائق رقمية فقط**. `generated_text_checked=false` مقصود؛ النص الحر
  لا يُعرض. لا تعني هذه النتيجة اعتماد توصيات علمية أو تنفيذ ري/تسميد.
- جرّب في بيئة اختبار معزولة: قيمة مختلقة، حالة تغيّرت أثناء التوليد، field لمستأجر
  آخر، إخراج حر، ومعرّف candidate مختلق؛ كلها تبقى محجوبة.
- غياب إيصال التدقيق أو فشل حفظه يمنع نشر الحقائق المولّدة، ويبقى جواب الأدلة.
- كتالوج مقترحات القرار لم يُوصّل لهذا المسار؛ `candidate_ids` يجب أن تبقى فارغة.
  لا يُستدعى `/v1/validate` كفاحص نصوص. تقييم الأفعال يحتاج candidates من مالك القرار
  و`/v1/evaluate`؛ هذا القيد ما زال مفتوحًا ولا يُحل بتعطيل الحجب.

## 6. الراستر وVegetation

- اقرأ الأصول الـ15 المبلغ عنها: المعرّف، المؤشر، الحالة، valid_pixel_ratio،
  acquisition_date وquality flags. تحقّق من COG والقناع: هل النسبة صفر حقيقي أم
  metadata بائتة؟ لا تحوّل صفرًا أو NULL إلى قياس صالح.
- القراءة المعدّلة تستبعد الأصول القديمة ذات النسبة صفر حتى لو بقيت حالتها ready؛
  الكاتب الجديد يحفظ الأصل الفارغ بحالة failed وعلم no_valid_pixels لأغراض التشخيص.
- تأكد أن سلسلة الزمن وobservation bundle لا تعيدها كقياسات، وأن قياس NDVI=0
  مع valid_pixel_ratio موجب يبقى مقبولًا؛ قيمة المؤشر صفر تختلف عن غياب البكسلات.
- افحص UID/GID وصلاحيات مجلد `/data/vegetation` وملفات SQLite وWAL/SHM عند وجودها.
  Dockerfile يهيّئ المجلد للحاويات الجديدة؛ volume قديم يحتفظ بملكيته القديمة.
  أصلح ملكية مسار البيانات المحدد للمستخدم الفعلي بعد توثيق الحالة والنسخ الاحتياطي؛
  لا تستخدم chmod 777 ولا تحذف قاعدة البيانات.
- أثبت وجود راوتري anomalies وdiagnoses في OpenAPI. فشل import يجب أن يظهر في
  `/readyz` بـ503 مع `router_import_failures`؛ liveness يبقى 200.

## 7. TTS وEdge والمحاكاة العلمية

- اختبر POST `/tts/synthesize` من frontend بالاعتماد نفسه المستخدم في المتصفح.
  المطلوب محتوى صوتي، لا HTML ولا 405. بدون اعتماد: رفض؛ tenant مزور لا يمر.
- استخدم نص اختبار غير حساس؛ المزود الحالي edge_tts سحابي. سجّل المزود الفعلي.
- Edge: أرجع عقود input/output والأبعاد/preprocessing/labels ووحدات yield ومصدر
  اعتماد نموذجَي ONNX وبصمتيهما. لا يكفي ملفان بالاسم المطلوب. بعد التزويد اختبر
  الاستدلال عبر المستهلكين وسجّل provider الفعلي، ثم اختبر فشل البصمة وعدم وجود الملف.
- agriai-engine وwofost-mcp: أرجع Python ونسخة pcse أو سبب غيابها، requirements
  للصورة، ومدخلات crop/soil/weather. إن كان المسار fallback فيبقى موسومًا بذلك.
  تفعيل المسار العلمي يحتاج تشغيل مثال مرجعي ومقارنة النتائج؛ تثبيت الحزمة وحده لا يكفي.
- تقييم العربية: مجموعة أسئلة ثابتة من محاصيل المزرعة؛ قياس الاستناد للمصدر، صحة
  الوحدات، رفض اختلاق الجرعات، والذاكرة/الزمن. لا تُفعّل vLLM إلى جوار Ollama وSAM2
  قبل قياس ذاكرة التزامن. لا يُغيّر embedding model دون خطة إعادة فهرسة مستقلة.

## 8. NATS والقرارات

- أرجع `/varz` بعد تنقيحه: وقت بدء الخادم، in_msgs/out_msgs والاتصالات. ومن JetStream:
  config.retention، state.messages، first_seq/last_seq، ومؤشرات consumers/ack_pending.
- حدّد وظيفة كل عميل من الشيفرة واشتراكاته؛ الاسم وحده لا يثبت أنه ناشر أو مستهلك.
- اقرأ outbox للـ17 حدثًا: حالة، attempts، آخر خطأ ووقت الإنشاء ونوع الحدث؛ دون payload
  حساس. حدّد العامل المالك، شروط إقلاعه، واتصاله الفعلي.
- علم FEATURE_NATS_PUBLISHERS يبقى افتراضيًا false في الشيفرة؛ قبل التفعيل على v25
  تحقّق من المستهلكين والوجهات وآثار backlog. لا تُعد إرسال أحداث قد تنفذ إجراءات
  مادية أو إشعارات لأشخاص أثناء تجربة غير معزولة.
- في مستأجر/stack اختبار معزول، فعّل الناشر وأثبت انتقال حدث تجريبي عبر outbox
  إلى ACK ثم المستهلك. إعادة التسليم يجب ألا تكرر الأثر التجاري. سجّل سبب أي توقف.
- decision-service: ثبّت نمط التخزين ومالك decision_record والمستهلك المقصود قبل
  تفعيل SOR. فراغ المرآة لا يستدعي إنشاء مالك بيانات ثانٍ.
