# تشغيل طرفية Xiaozhi على صوت سهول المحلي

هذه الإضافة تنفذ موائمًا اختياريًا بين Firmware Xiaozhi وخدمات الصوت القائمة في سهول. لا تستبدل برنامج الحساسات والصمام. الأساس الذي أُعدت عليه الرقعة هو `0fe280fe27bbba5d2cdfc3909642d1e9f55735fa`، ومصدر بروتوكول Xiaozhi المفحوص `78/xiaozhi-esp32@92d400d6374bbe750e0a0188fa969fc4042820c2`.

## السلوك المنفذ

المسار: جهاز → WSS/Opus → PCM16 mono 16kHz → `LocalWhisperSTT` → `HttpVoiceProviders` → المستشار القائم → TTS محلي → PCM48kHz → Opus → الجهاز. يعاد استخدام `voice_read_only=true` والتحقق من إيصال الإجابة والسياق، دون أدوات تنفيذ أو اعتماد أو أوامر مضخات. لا يحتاج هذا المسار غرفة LiveKit، وتظل جلسات LiveKit القائمة مستقلة.

تنفذ البوابة أغلفة WebSocket للإصدارات 1 و2 و3. يقبل hello صوت Opus أحادي القناة 16kHz بإطار20/40/60ms؛ ويعلن الخادم خرج48kHz أحادي القناة بإطار60ms. تُرفض الحزم المشوهة والأطوال غير المطابقة وstereo، ويُفحص حجم PCM بعد فك الترميز. مدخل الجولة15 ثانية كحد أعلى، والخرج المجمع45 ثانية. `manual` و`auto` مدعومان؛ `realtime` الكامل مرفوض في هذا الملف لأن قبول AEC لم ينجز. يستخدم auto كاشف الطاقة القائم، وليس نموذجًا جديدًا لجودة الصوت في الحقل.

الكود:

- `services/realtime-session/realtime_session/xiaozhi_gateway.py`: HTTP/WSS والجولة الصوتية.
- `services/realtime-session/realtime_session/xiaozhi_leases.py`: الموافقة وربط الهوية والإبطال.
- `services/realtime-agent/realtime_agent/xiaozhi_codec.py`: ترميز Opus وأغلفة النقل.
- `services/realtime-session/xiaozhi_main.py`: نقطة التشغيل المستقلة.

## الهوية والموافقة

يطلب عميل إدارة موثوق جلسة قصيرة بواسطة **Bearer المستخدم الحالي** مع `field_id` وMAC في `device_id` وUUID في `client_id` و`consent=true` و`voice_consent=true`. تقرأ السلطة الأصلية `/api/v1/me` ثم الحقل، وتفرض السياسة المحلية v52. لا يحدد العميل المستأجر ولا صلاحيات الأدوات في جسم الطلب.

تعيد البوابة رمزًا عشوائيًا خاصًا بالجهاز لمدة300 ثانية واتصال واحد. يتطلب اتصال الجهاز الرمز و`Device-Id` و`Client-Id` المطابقين. MAC وUUID معرفان للربط، وليسا إثبات هوية مستقلين؛ السر هو اعتماد الاتصال. يعاد التحقق من المستخدم والحقل والسياسة قبل المعالجة وبين مراحلها، وبحارس مستقل كل ثانيتين، مع مؤقت انتهاء منفصل. رفض المصدر أو إبطال الجلسة يوقف المسار. إلغاء جولة بسبب المقاطعة لا يسقط الجلسة كلها.

السعة المحلية: جلسة واحدة للمستخدم، واحدة لمعرف الجهاز، أربع للمستأجر، وست عشرة للعملية. التسجيلات والأسرار في الذاكرة فقط وتزول عند إعادة تشغيل الخدمة. التشغيل **عملية واحدة فقط**؛ لا يدعي هذا السجل حصة موزعة بين نسخ متعددة. إعادة الاتصال تتطلب إصدار جلسة جديدة، ولا يعاد تنفيذ كلام أو فعل تلقائيًا بعد فقد الاتصال.

## التهيئة المطلوبة

التشغيل الافتراضي معطل: `SAHOOL_XIAOZHI_ENABLED=0`. تبني هذه الأوامر صورة مستقلة من الجذر:

```bash
docker build -f services/realtime-session/Dockerfile.xiaozhi -t sahool-xiaozhi:review .
docker run --rm --network none sahool-xiaozhi:review
```

الأمر الثاني يختبر خروج الصورة المعطلة دون شبكة أو نماذج. ملف Docker يعيد استخدام متطلبات `realtime-agent` و`realtime-session` المثبتة؛ لا يضيف نسخة تبعيات موازية. بوابة CI في `.github/workflows/realtime-agent.yml` تشمل اختبارات الموائم وبناء صورته؛ إضافة الخطوة لا تعني أن CI شغلت في جلسة إعداد الرقعة.

عند إعداد بيئة الاختبار الفعلية، ضع متغيراتها في ملف محمي خارج Git، واربط نموذج Whisper كاملًا للقراءة فقط. هذه قائمة المتغيرات وليست ملف أسرار جاهزًا:

| المتغير | القيمة/المعنى |
|---|---|
| `SAHOOL_XIAOZHI_ENABLED` | `1` لتشغيل الموائم بعد تجهيز المتطلبات |
| `XIAOZHI_PUBLIC_WSS_URL` | عنوان عام مشفر ينتهي حرفيًا بـ`/xiaozhi/v1/` |
| `XIAOZHI_TRUSTED_PROXY_IPS` | عنوان الوكيل العكسي الموثوق فقط؛ الافتراضي loopback؛ لا تستعمل `*` |
| `PLATFORM_API_URL` | مصدر هوية سهول وقراءة الحقل؛ مثل `http://sahool-platform:8000` داخل شبكة الخدمات |
| `REALTIME_AI_ORIGIN` | أصل BFF الموثوق الذي يقدم `/api/ai-agronomist/chat` |
| `REALTIME_TTS_ORIGIN` | أصل BFF الموثوق الذي يقدم `/tts/synthesize` |
| `REALTIME_TTS_PROVIDER` | `piper` أو `xtts` بحسب المزود المحلي المتاح فعليًا |
| `REALTIME_STT_MODEL_PATH` | المسار المطلق للنموذج المركب داخل الحاوية |
| `REALTIME_STT_MODEL_SHA256` | بصمة ملف `model.bin` المقبول |
| `REALTIME_STT_BUNDLE_SHA256` | بصمة الحزمة الكاملة، وفق README عامل الصوت |

لا يقبل المصدر HTTP خارجيًا ولا تحويلات redirects للطلبات الحاملة للاعتماد. يجب أن تتصل البوابة فعليًا بالخدمات المقصودة داخل الشبكة، ويجب أن تبقى أعلام offline للنماذج مفعلة. راجع [قبول النماذج المحلية](LOCAL_VOICE_ACCEPTANCE_AR.md): وجود إعداد Piper أو اسمه لا يثبت تنزيل أوزان مرخصة أو نجاح النطق. هذه الرقعة لا توفر أو تُفعّل أوزانًا افتراضية.

المنفذ الداخلي8011. ضع وراء TLS reverse proxy موثوق، ومرر **فقط** مساري التسجيل `/api/v1/realtime/xiaozhi/leases` وما تحته، وWSS `/xiaozhi/v1/`. اضبط حد جسم HTTP4096 بايت وWebSocket4112 بايت؛ موائم التطبيق يفرضهما أيضًا، ونقطة Uvicorn تضبط طابور WebSocket4 وإلغاء الضغط. لا تعرض المنفذ الداخلي مباشرة ولا تمرر Cookie. يجب أن يضبط الوكيل `X-Forwarded-Proto` من اتصاله الفعلي، ولا يصدق قيمة يوردها العميل، وأن تطابق جهة الاتصال قائمة `XIAOZHI_TRUSTED_PROXY_IPS`؛ وإلا يرفض التطبيق الطلب بغياب HTTPS/WSS. التسجيل من عميل إدارة أصلي/خادمي؛ لا توجد واجهة تسجيل متصفح ولا CORS مفتوح في هذه الرقعة.

## رحلة التسجيل والاستخدام

1. جهز اللوحة المدعومة وفق تعليمات Xiaozhi، وحدد `Device-Id` و`Client-Id` الحقيقيين، ولا تستبدل Firmware الصمام الزراعي به.
2. اطلب جلسة من `POST /api/v1/realtime/xiaozhi/leases` بترويسة `Authorization: Bearer <رمز المستخدم>` وجسم JSON:

   ```json
   {
     "field_id": "<معرف الحقل المصرح>",
     "device_id": "aa:bb:cc:dd:ee:ff",
     "client_id": "00000000-0000-4000-8000-000000000001",
     "consent": true,
     "voice_consent": true
   }
   ```

3. يضم الرد `session_id` و`expires_at` و`websocket.url/token/version`. ضع **رمز الجهاز المعاد فقط** في إعداد WebSocket في Firmware؛ لا تخزن JWT المستخدم أو مفتاح خدمة على الجهاز. يحفظ المستخدم استجابة التسجيل بما يلائم حساسيتها؛ التطبيق يرسل `Cache-Control: no-store` ويعطل access log في نقطة التشغيل.
4. اتصل بالعنوان عبر WSS. ترويسات الجهاز: `Authorization: Bearer <رمز الجهاز>` و`Device-Id` و`Client-Id` و`Protocol-Version: 1`. يبدأ الجهاز hello، ثم listen والصوت. جميع رسائل التحكم اللاحقة تتطلب `session_id` الذي أعاده hello.
5. لإيقاف الجلسة: `DELETE /api/v1/realtime/xiaozhi/leases/{session_id}` برمز صاحبها. يستطيع صاحبها إغلاقها بعد فقد صلاحية الحقل ما دامت هويته صحيحة. انتهاء300 ثانية أو إعادة تشغيل الخدمة يلغي الاعتماد أيضًا.

هذه رحلة تهيئة قصيرة قابلة للتجربة، وليست خدمة تسجيل OTA تلقائيًا أو تجديدًا دائمًا للأجهزة. يختلف موضع إدخال إعداد WebSocket حسب بناء ولوحة Xiaozhi؛ لا تفترض أن نشر ملف OTA على خادم آخر قد تم. المصدر الرسمي لعقد الإعداد: [وثيقة WebSocket المثبتة](https://github.com/78/xiaozhi-esp32/blob/92d400d6374bbe750e0a0188fa969fc4042820c2/docs/websocket.md).

## حدود الوقت والخصوصية

إعداد الإجابة في `TurnRunner` محدود45 ثانية. يستعمل هذا الموائم مهلة نشر65 ثانية، منها حد15 ثانية لتجهيز Opus وإعادة التحقق قبل بدء TTS، ثم45 ثانية صوت مع سماح بسيط للإطارات. يظل حد خمول القراءة120 ثانية حتى لا يقطع صمت الميكروفون أثناء الرد. كل هذه الحدود تابعة لمؤقت انتهاء الجلسة وحارس الإبطال. تأخر الشبكة أو الإبطال قد يوقف خرجًا بدأ بالفعل؛ لا يمكن سحب صوت سمعه المستخدم أو بقي قليل منه في سماعة الجهاز.

تجمع خدمة الصوت أجزاء الإجابة قبل نشرها حتى لا يترك فشل جزء لاحق نصيحة ناقصة التجهيز. النص الطويل يمر بحارس النص الكامل، وتحتاج خدمة TTS المحدّثة ترويسة `X-Speech-Validation: full-context-v1`. حد8000 حرف ليس وعدًا بنطق دقائق كاملة، إذ يبقى حد الصوت45 ثانية.

لا تخزن البوابة التسجيلات أو الرموز أو النصوص. تدقيق سؤال المستشار وإجابته في الخدمات الأصلية يبقى قائمًا؛ `no_store` يخص كاش TTS. تُهمل مقاطع الإيقاظ السابقة لبدء الاستماع ولا تحال إلى المستشار، لكن Firmware قد يرسلها عبر الشبكة حسب `SEND_WAKE_WORD_DATA`؛ عطله في بناء الجهاز إذا كان المطلوب ألا تغادر اللوحة أصلًا. رسائل MCP الواردة من الجهاز لا تولد استدعاءات أدوات. للحصول على أدوات سحابية منفصلة راجع [MCP للقراءة](XIAOZHI_MCP_READ_ONLY_AR.md).

## التحقق والتراجع

```bash
python -m pip install -r services/realtime-agent/requirements.txt \
  -r services/realtime-session/requirements.txt pytest pytest-asyncio
python -m pytest -q -o addopts='' services/realtime-agent/tests/
```

الاختبارات تنفذ ترميز Opus حقيقيًا ومسار WebSocket داخل العملية، باستخدام بدائل مضبوطة للمستشار والنموذج. تغطي الربط، والإبطال، والمقاطعة، وإعادة الاتصال، ورفض الأنواع والأحجام غير المتوافقة، وعدم تحول رسالة MCP إلى أمر. لا تثبت هذه الاختبارات جودة اللهجة أو الميكروفون أو AEC أو إعداد CA على اللوحة أو زمن الاستجابة في الحقل.

التراجع: أوقف بوابة Xiaozhi أو أعد العلم إلى0، وأزل توجيهها من الوكيل. تبطل كل جلسات الذاكرة. لا توجد هجرة قاعدة بيانات أو حاجة لإزالة سياق LiveKit. إذا رجعت عن تحديث TTS فارجع عن العامل الطويل معه أو اتركه معطلًا؛ التوافق يرفض الخدمة القديمة عمدًا. لا يفعّل هذا الدليل MQTT أو قواعد التشغيل؛ إعداد تلك الطبقة موثق مستقلًا في [ملف أجهزة MQTT](MQTT_DEVICE_PROFILE_AR.md).

قبل القبول الميداني: لوحة وبناء معروفان، نموذج عربي مرخص ومقبول، رحلة فعلية من الميكروفون إلى السماعة، اختبار شبكة ضعيفة وانقطاع، إبطال أثناء النطق، ورفض طلب تشغيل المضخة في وضع القراءة. سجّل نتائجها بوصفها قبولًا منفصلًا، ولا ترفع حالة هذه الأعمال إلى تشغيل مثبت بمجرد نجاح اختبارات الشيفرة.
