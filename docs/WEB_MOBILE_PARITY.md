# تكافؤ الويب والموبايل — مصفوفة موحّدة + العقد المشترَك

> **المبدأ:** الويب (React/TypeScript) والموبايل (Flutter/Dart) **منصّتان مختلفتان
> بلا قاعدة كود واجهة مشترَكة** — فلا نزعم توحيداً غير موجود. ما يوحّدهما فعلاً هو
> **العقد المشترَك**: مسارات `‎/api/v1/*` نفسها، ونموذج صلاحيّات (RBAC) واحد،
> ودلالات حالات صادقة واحدة. هذه الوثيقة هي المصدر الواحد لحالة التكافؤ.

آخر تحديث: ضمن جلسة «دمج شاشات الويب» (بناء عارض الحوكمة + توثيق التكافؤ).

---

## ١. العقد المشترَك (مصدر الحقيقة الوحيد لكلتا المنصّتين)

| البُعد | التفصيل |
|---|---|
| **الـAPI** | كلّ الأنظمة التشغيليّة تحت `‎/api/v1/*` عبر البوّابة (Kong). الويب: `kongApi` (axios). الموبايل: `ApiService` (Dio). نفس المسارات والحقول وأكواد الحالة. |
| **RBAC** | خمسة أدوار: `owner, manager, agronomist, worker, viewer`. تطبيع الأسماء المرادفة، **fail-closed إلى viewer**. `canMutate` (الكلّ عدا viewer)، `canManage` (owner/manager فقط). الويب: `lib/permissions.ts`. الموبايل: `lib/permissions.dart` (متطابقان منطقيّاً). |
| **الصدق** | لا بيانات مُلفَّقة في أيّ منصّة. حالة الخطأ تُعرَض كما هي: **503 → قاعدة البيانات معطّلة، 403 → لا صلاحيّة، 404 → غير موجود**. الويب: `StateViews.tsx`. الموبايل: `widgets/state_views.dart`. |
| **المستأجِر** | كلّ الاستعلامات مفهرَسة بـ`tenantId` من الجلسة؛ الخادم يطبّق RLS (FORCE) على مستوى قاعدة البيانات. |

> أي تغيير في عقد الخادم يجب أن يُعكَس في **الملفّين** (`api.ts` و`api_service.dart`)
> وفي **منطق الصلاحيّات** (`permissions.ts` و`permissions.dart`) معاً.

## ٢. مصفوفة التكافؤ (نظام × ويب × موبايل × خلفيّة)

| النظام | خلفيّة `‎/api/v1` | شاشة ويب | شاشة موبايل | الوصول |
|---|:---:|:---:|:---:|---|
| لوحة المعلومات | ✅ | ✅ `DashboardPage` | ✅ `dashboard_screen` | الكلّ |
| المؤشّرات/الأقمار | ✅ | ✅ `Hybrid/Satellite` | ✅ `satellite_screen` | الكلّ |
| الحقول | ✅ | ✅ `FieldManagement` | ✅ `fields_screen` | الكلّ |
| المستشار الذكيّ | ✅ | ✅ `ChatbotPage` | ✅ `advisor_screen` | الكلّ |
| **المخزون** | ✅ | ✅ `InventoryPage` | ✅ `inventory_screen` | عامل+ |
| **المعدّات** | ✅ | ✅ `EquipmentPage` | ✅ `equipment_screen` | عامل+ |
| **أجهزة IoT** | ✅ | ✅ `DevicesPage` | ✅ `devices_screen` | عامل+ |
| **الري التشغيلي** | ✅ | ✅ `IrrigationOpsPage` | ✅ `irrigation_ops_screen` | عامل+ |
| **البيانات المرجعيّة** | ✅ | ✅ `MasterDataPage` | ✅ `master_data_screen` | إدارة فقط |
| **الوثائق** | ✅ | ✅ `DocumentsPage` | ✅ `documents_screen` | إدارة فقط |
| **الحوكمة والتدقيق** | ✅ | ✅ `GovernancePage` | ⬜️ (لاحقاً) | إدارة فقط |
| الإعدادات/الحساب | ✅ | ✅ `SettingsPage` | ✅ `profile_screen` | الكلّ |

**الحوكمة والتدقيق** (جديد) يغطّي الأنظمة الخلفيّة التي لم يكن لها واجهة:
أصل الكيان (`lineage`)، أحداثه (`events`)، البحث عن أمر (`commands`)، ومفاتيح
المشاركة (`sharing`). قراءة-غالباً + إنشاء مفتاح؛ كلّها DB-backed (503 عند تعطّل DB).

### ملاحظات تشغيليّة صادقة (متطابقة عبر المنصّتين)
- **الري:** تغيير حالة الصمّام يسجّل **النيّة فقط**؛ التشغيل الفيزيائيّ بموافقة بشريّة (HIL).
- **الوثائق:** سجلّ **بيانات وصفيّة** + `storage_ref` — ليس رفع ملفّ.
- **الأجهزة:** تُعرَض القياسات **الحقيقيّة فقط** مع مؤشّر online/offline مُحتسَب خادميّاً.
- **مفتاح المشاركة:** النصّ الكامل يُعرَض **مرّة واحدة** بعد الإنشاء.

---

## ٣. تنقّل المنصّتين

- **الويب:** شريط جانبيّ مُرشَّح بـ`canAccess` — الصفحات الإداريّة (البيانات المرجعيّة/
  الوثائق/الحوكمة) لا تظهر لغير owner/manager.
- **الموبايل:** خمسة تبويبات أساسيّة + تبويب **«العمليّات»** يفتح شبكة وحدات مُرشَّحة
  بالـRBAC (البيانات المرجعيّة/الوثائق إدارة فقط). لا تبويب قائم أُسقِط.

---

## ٤. الفجوات المتبقّية في التكافؤ (صادقة)

| الفجوة | الحالة | شرط الإغلاق |
|---|---|---|
| شاشة حوكمة للموبايل | الويب فقط حاليّاً | جلسة بناء Flutter (نمط on-demand lookup) |
| تحقّق بناء الموبايل | لا Flutter SDK في البيئة | `flutter analyze` في بيئة فيها SDK |
| سلوك DB حيّ (lineage/events/commands/sharing) | الكود جاهز، يُرجِع 503 offline | PostgreSQL حقيقيّ |

> التكافؤ الحاليّ: **١٠/١٠** أنظمة تشغيليّة على المنصّتين، + الحوكمة على الويب.
> الموبايل يغطّي ٦/٦ من الأنظمة التشغيليّة الجديدة عبر `‎/api/v1/*` الحقيقيّة.
