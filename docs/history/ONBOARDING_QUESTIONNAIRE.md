# استبيان استيعاب البيانات التاريخيّة — منصّة سهول

> **الغرض:** قبل بناء أيّ نموذج (yield prediction, neighbor comparison,
> data assimilation)، نحتاج فهم شكل البيانات الفعليّة الموجودة عند
> المزارعين والشركاء. هذا الاستبيان يحدّد ما يستحقّ البناء وما لا.
>
> **المبدأ الحاكم:** "النضج = معرفة متى لا تبني، والـtrigger الفعلي
> = بيانات/معدّات، لا فكرة." بدون الإجابات، أي كود نبنيه هو افتراضات
> قد تحتاج لإعادة كتابة.

## القسم ٣: جودة البيانات (Data Quality)


### ٣.٢ مصدر الحقيقة (Source of Truth — لكل عمود)

> هذا القسم حاسم لـsource_of_truth.py الموجود في النواة.

| الحقل | المصدر | الثقة |
|-------|--------|-------|
| الإنتاج | ☐ ميزان فعلي  ☐ تقدير المزارع  ☐ تقدير عَيني | ☐ عالية ☐ متوسطة ☐ منخفضة |
| المساحة | ☐ مساح بـGPS  ☐ تقدير  ☐ من cadastre | ☐ عالية ☐ متوسطة ☐ منخفضة |
| تحاليل التربة | ☐ لاب معتمد  ☐ لاب محلّي  ☐ تقدير | ☐ عالية ☐ متوسطة ☐ منخفضة |
| الكميّات (سماد/بذر) | ☐ موثَّق بفواتير  ☐ ذاكرة المزارع | ☐ عالية ☐ متوسطة ☐ منخفضة |
| التواريخ | ☐ مُسجَّل وقتها  ☐ مُسترجَع لاحقاً | ☐ عالية ☐ متوسطة ☐ منخفضة |

## القسم ٧: ما لا يُبنى الآن

> هذا القسم لأكون صريحاً معك: حتى لو كان لديك البيانات،
> هذه الأشياء **لن تُبنى بدون triggers إضافيّة**:

| الميزة | trigger المطلوب |
|--------|-----------------|
| `data_assimilation` (LAI → WOFOST) | موسمَين Sentinel-2 من نفس الحقل |
| `eta_sebal` (R10 ET map) | حسّاس thermal (Sentinel-3/Landsat 8) |
| Voice interface عربي | STT/TTS offline مفتوح المصدر |
| Spate irrigation engine | مزرعة فعليّة تستخدم spate |
| Groundwater depletion model | well log measurements |
| `data_inventory` planned items | كل واحد له trigger منفصل |

**هل أيّ من هذه يطابق وضعك الفعلي؟**

```
☐ نعم — نملك ____________________ (حدّد)
☐ لا — كلّها لا تنطبق علينا الآن
```

> أكبر مساعدة الآن: **١٠-٢٠ صفّ عيّنة فعليّة** من بياناتك،
> حتى لو فوضويّة، حتى لو ناقصة. الـ`historical_onboarding`
> سيُحلّلها ويُولِّد تقريراً يكشف:

> - مشاكل الجودة
> - مستوى الجاهزيّة (`ready` / `needs_review` / `blocked`)

**هل يمكن إرفاق عيّنة؟**

```

☐ نعم، قريباً

```

## المرحلة التالية بعد إجابتك

```
لو الإجابات تكشف:
  • Excel/CSV منظَّمة، 50+ سجل، إنتاج+مساحة+تاريخ
    → نبني yield_metrics + Mobile import screen

  • Excel فوضويّة
    → نبني data_cleansing layer قبل ingestion

  • PDFs/دفاتر ورقيّة
    → نبني UI manual entry بـtemplate موحَّد
    → لا OCR (خارج النطاق حالياً)

  • أقلّ من ٢٠ سجل
    → لا ML، نواة سهول الحاليّة (rules+WOFOST) كافية
    → نُركّز على farm_ledger + portfolio + drawing tools
```

**الشيء الوحيد المؤكَّد:** بناء `yield_metrics.py` بـschema مفترَض
قبل رؤية البيانات = إهدار. الإجابة على هذه الأسئلة توفّر أسابيع.
