# أصل ونسخة نتائج الراستر (البند #7)

## المشكلة (المراجعة #7)
نتائج المؤشّرات (NDVI، ملوحة...) كانت تُعاد بلا تسجيل مصدرها → بعد أشهر لا
تعرف أيّ صورة/تاريخ/معاملات أنتجتها. "ثقة زائفة" في رقم غير قابل للتحقّق.

## الحلّ
جديد: raster_provenance.py — لكلّ نتيجة سجلّ أصل كامل:
- scene_id (الصورة المثبّتة) + capture_datetime (وقت التقاط القمر)
- raster_url (الأصل) + source_format
- indicator + formula_version (نسخة الصيغة — تغيّرها = نتيجة مختلفة)
- معاملات: cloud mask، band mapping، clip polygon hash
- CRS + الدقّة
- **provenance_hash**: بصمة sha256 تجمع كلّ المدخلات المؤثّرة

مدموج في نتيجة المعالجة (job result + layer).

## الفوائد
- إعادة الإنتاج: نفس المدخلات → نفس البصمة (verify_provenance_match)
- كشف الاختلاف: صورة/تاريخ مختلف → بصمة مختلفة
- الصدق: مصدر ناقص → is_reproducible=false (لا ثقة زائفة)

## ⚠️ ملاحظات صدق
- يثبّت **المدخلات** لإعادة الإنتاج. الإعادة البِتّيّة (bit-exact) تتطلّب
  أيضاً تثبيت نسخة rasterio/GDAL — حقل rasterio_version موجود لكن لا يُفرَض
  (يحتاج بيئة تشغيل مثبّتة). هذا تثبيت منطقي لا بِتّي.
- العميل (من يستدعي /process) يجب أن يمرّر scene_id + capture_datetime من
  نتيجة STAC search السابقة. بلا ذلك → النتيجة موسومة "غير قابلة للإعادة"
  (صادقة، لا تدّعي ما لا تملك).
- tile provenance hashes الفرديّة (لكلّ بلاطة) لم تُنفّذ — البصمة على مستوى
  النتيجة لا البلاطة. كافٍ لإعادة الإنتاج؛ tile-level تحسين لاحق.
