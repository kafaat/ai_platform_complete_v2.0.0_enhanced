# ربط raster-service بشاشة الخريطة (طبقة NDVI فوق الحقل)

## الفجوة المكتشفة
MapScreen كان يعرض البلاطة فقط إن وُجد `active_layer_id` مُسبق (stub) — لا
يوجد تدفّق فعلي لإنشاء الطبقة (بحث صورة → معالجة → عرض).

## الحلّ
### دالّة التدفّق المتكامل (raster.ts)
`generateFieldIndicatorLayer(bbox, tenantId, indicator, opts)`:
١) يبحث عن آخر صورة Sentinel-2 صافية (searchRecentImagery)
٢) يبدأ معالجة المؤشّر على روابط نطاقاتها (processRaster)
٣) ينتظر اكتمال المهمّة (pollJobUntilDone)
٤) يُرجع الطبقة جاهزة (layer_id + tile_url + bounds + stats + تاريخ الصورة)
+ `bboxFromPolygon(polygon)`: يحسب bbox من مضلّع الحقل

### الربط في MapScreen
- زرّ "🛰️ حدّث طبقة NDVI من آخر صورة" ينفّذ التدفّق للحقل الفعّال
- حالات واضحة: جارٍ المعالجة / نجاح (تاريخ+غيوم+متوسّط) / لا صور صافية / خطأ
- الطبقة الناتجة تُعرض فوق الحقل على MapLibre (tileUrlTemplate + bounds)
- تبديل المؤشّر (NDVI/EVI/...) يعيد ضبط الحالة

## التحقّق
- ✓ التدفّق الكامل موصول (بحث → معالجة → انتظار → عرض)
- ✓ كلّ الحقول متطابقة (layer_id/indicator/bounds_4326/stats/tile_url_template)
  بين raster.ts ← raster-service
- ✓ فحص TypeScript للمشروع كامل: صفر أخطاء منطقيّة (أصلحتُ 4 implicit any)
- ✓ المؤشّرات RGB-only (vari/gli/tgi) تتعامل دون NIR بشكل صحيح

## مبدأ الصدق
- حالة "لا صور صافية" معالَجة صراحةً (لا يدّعي طبقة وهميّة)
- حالة الخطأ معالَجة (لا ينهار)
- يعرض بيانات الصورة الفعليّة (تاريخ/غيوم/متوسّط المؤشّر) للشفافيّة

## الأثر
ميزة عرض المؤشّرات النباتيّة على الخريطة صارت **تدفّقاً كاملاً قابلاً
للتشغيل**: المزارع يضغط زرّاً → النظام يجلب آخر صورة قمر صناعي لحقله →
يحسب NDVI → يعرضه ملوّناً فوق حقله. النظام متّصل: الجوال → raster-service
(8001) → Element84 → بلاطات MapLibre.
