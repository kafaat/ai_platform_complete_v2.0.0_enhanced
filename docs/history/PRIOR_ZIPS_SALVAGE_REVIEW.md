# مراجعة النسخ السابقة (zip المرفوعة): ما نُقِل وما رُفِض

راجعتُ ١٢ حزمة zip سابقة (نسخ تاريخيّة من سهول). كلّها سليمة (الـ"تالف" كان
إنذار `unzip` كاذباً بسبب القراءة-فقط؛ python testzip = سليم). طبّقتُ نفس
مبدأ المراجعة: أنقل ما يسدّ فجوة حقيقيّة ويتوافق مع مبادئنا، وأرفض المكرّر
والمخالف.

---

## ما نُقِل (سدّ فجوة حقيقيّة + توافق مبدئي)

### ✅ chemical_safety.py (من sahool_v9_integrated/guardrails_engine/tiers)
**فجوة سلامة حقيقيّة:** لم يكن عندنا أيّ فحص للمواد الكيميائيّة المحظورة.
المكوّن السابق فحص/تحذير محض (لا أتمتة تطبيق) → يتوافق مع "السلامة لا تُتجاوز".
كيّفتُه لمعماريّتنا (نمط ChemicalStatus، عربي، وسم المصادر):
- ١٤ مادّة محظورة/مقيّدة دوليّاً (استكهولم/مونتريال/EU/EPA) → BLOCKED
- جرعات قصوى + مناطق عازلة + فترات إعادة دخول
- مادّة مجهولة → تحذير (لا نؤكّد سلامة مجهول)
Endpoints: POST /chemical-safety/check, GET /chemical-safety/banned. 6/6 اختبار.

## ملاحظة منهجيّة

أغلب النسخ السابقة **مكرّرة** مع عملنا الحالي (الأحدث والأنضج) — وهذا متوقّع،
فهي مراحل تطوّر سابقة. القيمة الوحيدة غير المكرّرة وغير المخالفة كانت
**فحص السلامة الكيميائيّة** — فجوة حقيقيّة سُدَّت.

الباقي إمّا بنيناه أفضل، أو يخالف مبادئنا (أتمتة، ML بلا بيانات)، أو مؤجّل
بانتظار حاجة مثبتة. لم أنقل شيئاً "لمجرّد أنّه موجود" — كلّ نقل مرّ بمسطرة:
هل يسدّ فجوة؟ هل يتوافق مع السلامة وhuman-in-the-loop والصدق العلمي؟
