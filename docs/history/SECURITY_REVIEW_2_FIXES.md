# مراجعة أمنيّة ٢ — حاوية البوت + مسح منهجي (تحقّقتُ من كلّ ادّعاء)

## ✅ ثغرات السلامة/الأمان الحرجة (مُصلَحة)

### actuator /command — تحكّم فيزيائي بلا مصادقة (الأخطر)
كان أيّ طرف على الشبكة يتحكّم بصمّامات الريّ/المضخّات، وtenant_id من جسم
الطلب. الإصلاح: Depends(_verify_token) + tenant_id يُشتقّ من التوكن المُتحقَّق
لا الجسم + فشل آمن لو JWT_SECRET فارغ/قصير (HS256 بمفتاح فارغ يقبل تزويراً).

### guardrails /approve — تجاوز البوابة البشريّة بلا مصادقة
كان أيّ طرف يوافق على إجراءات محجوزة، وexpert_id من query. الإصلاح:
Depends(_gr_verify) يتطلّب دور expert/admin + expert_id من التوكن لا الطلب.

### odoo-bridge /sync + /webhook/odoo — ERP مكشوف
verify_token كان معرّفاً وغير مُستدعى (كود ميت). الإصلاح:
- /sync: يتطلّب Bearer token صالح (يكتب لـERP)
- /webhook/odoo: يتطلّب X-Webhook-Secret = WEBHOOK_SECRET (منع حقن خارجي)

## ✅ حاوية البوت (B1-B6)

### B5 — الأخطر: البوت يصكّ توكنات JWT اعتباطيّة (مُصلَح)
كان get_user_token يصكّ JWT بهوية اعتباطيّة موقّعاً بالسرّ المشترك → أيّ
مستخدم تيليجرام يحصل على توكن منصّة بلا تسجيل. الإصلاح الجذري:
- البوت لم يعد يصكّ توكنات ولا يحمل سرّ التوقيع (أُزيل JWT_SECRET)
- get_user_token يُرجع التوكن المربوط فقط (None لو لم يُربط → الخدمات ترفض)
- link_account(): يصادق ضدّ auth/login ويخزّن التوكن الشرعيّ الصادر منها

### B1 — سطر apt مشوّه (مُصلَح)
`\ curl \` (شرطة + مسافة) → الشرطة الآن آخر محرف، السطر نظيف.

### B3 — crash-loop لا نهائي (مُصلَح)
raise RuntimeError عند غياب التوكن + restart:unless-stopped = حلقة. الآن
خروج نظيف (exit 0) مع تسجيل — لا crash-loop.

### B4 — عدم تطابق أسماء المتغيّرات (مُصلَح)
الكود يقرأ WEBHOOK_SECRET لكن compose يمرّر TELEGRAM_WEBHOOK_SECRET. الآن
يقرأ الاسم الصحيح مع fallback.

### B2 — healthcheck (مُصلَح سابقاً)
Dockerfile فيه pgrep healthcheck صحيح بالفعل (لا HTTP وهمي).

## ⚠️ B6 — MARKDOWN_V2 بلا escaping (لم يُصلَح — قرار مقصود)
