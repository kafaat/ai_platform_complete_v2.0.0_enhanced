# تعميق قلب النظام: Redis cache + معالجة دفعيّة

تنفيذ التعميقين على قلب النظام (الاستشعار).

## ١. cache STAC مشترك عبر Redis (مرونة + كفاءة عبر النسخ)
**قبل**: cache بالذاكرة فقط (لكلّ نسخة، يضيع عند إعادة التشغيل).
**بعد**: cache طبقتان في stac_client.py:
- Redis (مشترك عبر كلّ نسخ raster-service، يبقى عبر إعادة التشغيل)
- ذاكرة (fallback)
- **تدهور لطيف**: فشل Redis → ذاكرة تلقائيّاً، لا تعطّل الخدمة (نفس فلسفة auth)
- TTL في Redis مضاعف ×4 للسماح بـstale-if-error بعد انتهاء الصلاحيّة
- REDIS_URL في compose (db منفصل)؛ redis>=5.0.0 في requirements
**الأثر**: نسخة تبحث منطقة → النسخ الأخرى تستفيد من cache فوراً. أقلّ ضغطاً
على Earth Search، أسرع، أمتن ضدّ الانقطاع.

## ٢. المعالجة الدفعيّة (عدّة مؤشّرات من مشهد واحد)
**قبل**: طلب /process لكلّ مؤشّر (يقرأ النطاقات مرّة لكلّ منها). الأتمتة
تحسب NDVI فقط.
**بعد**: /process/batch + BatchProcessRequest:
- طلب واحد يحسب عدّة مؤشّرات من نفس المشهد
- عزل فشل كلّ مؤشّر (فشل NDRE لا يُسقط NDVI/NDSI) — batch_results + batch_failed
- خلفيّة (لا يحجب)
**الأتمتة تستفيد**: مشهد جديد → NDVI (صحّة) + NDRE (نيتروجين) + NDSI (ملوحة —
حرج لليمن) دفعةً واحدةً بدل ثلاثة طلبات.
