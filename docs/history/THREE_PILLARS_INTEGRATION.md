# تدقيق مراجعة الأعمدة الثلاثة — تنفيذ الإصلاحات في المفاصل

مراجعة استثنائيّة الدقّة (قيّمت العقل/القلب/العمود الفقري + الحلقة التعلّميّة).
دقّقتُ كلّ ادّعاء بالكود ونفّذتُ الإصلاحات الحقيقيّة في المفاصل.

## ✅ الإصلاح الأعلى قيمة: حَوكمة بوّابة القرار (#1)
**المراجعة محقّة**: optimize_farm كان يحسب خطراً محلّيّاً
(abs(1-irr_mult)*10+...) بدل تمرير التوصية عبر بوّابة Guardrails القويّة.
البوّابة موجودة لكن ليست حاكمة للمسار.
**الإصلاح**: _validate_via_guardrails — التوصية المختارة تمرّ الآن عبر
Guardrails /validate (3 طبقات + HITL) قبل أن تصبح قابلة للتنفيذ. البوّابة
صارت مرجع الحقيقة الوحيد للقرار (العقل اتّحد بالعمود الفقري).
- صدق: عند تعذّر الوصول للبوّابة → governance.allowed=None + "لا تُنفَّذ
  تلقائيّاً" (لا يتظاهر بموافقة).

## ✅ صدق القلب: تسمية النموذج (#3)
**المراجعة محقّة**: "WOFOST" فعليّاً مقدّر RUE مبسّط (biomass=ΣPAR×RUE،
yield=biomass×HI) لا WOFOST يومي التكامل — يفوته توقيت الإجهاد الطوْري.
**الإصلاح**: وُحّدت التسمية الصادقة — "RUE-Estimator (FAO-56)" في المخرجات
+ docstring صريح يوضّح الحدود (تقدير درجة أولى يُحسّن بمعايرة TrueUp). لا
ادّعاء WOFOST كامل للمستخدم.

## ✅ حماية إعادة التشغيل: upcasting الأحداث (#4)
**المراجعة محقّة**: schema_version موجود (default 1.0) لكن لا upcasting —
حين يتغيّر شكل حدث، إعادة التشغيل تنكسر.
**الإصلاح**: event_upcasting.py — سجلّ مرقّيات (event_type, from_version) →
دالّة تحويل، يُطبَّق عند إعادة البناء (replay) قبل reconstruct. المخزن يبقى
append-only؛ الترقية في الذاكرة. قالب مرقٍّ موثّق للمستقبل.
- صدق: نوع غير مسجّل → يُترك كما هو (لا يخترع تحويلاً).

## ⚠️ مقايضة مؤجّلة واعية (#2 — أقرّت بها المراجعة)
التوسّع الأفقي (workers=1 + طابور/rate-limit بالذاكرة). الكود موسوم بصدق
"للإنتاج: Redis". خطوة جزئيّة: نقلتُ cache STAC لـRedis سابقاً. النقل الكامل
(الطابور + rate-limit) قرار نشر لا إصلاح ساكن — كما أقرّت المراجعة.
