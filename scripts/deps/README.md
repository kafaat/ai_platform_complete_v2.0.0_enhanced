# قفل تبعيّات Python (Dependency Locking)

معالجة فجوة سلسلة الإمداد التي رصدها تدقيق خارجيّ: ملفّات `requirements*.txt`
تستخدم نطاقات (`>=`/`<`) فيختلف الـbuild بين يومٍ وآخر. القفل يُثبّت النسخ
المُحلَّلة بالكامل (transitive + hashes) للمسار الحرج.

## حلٌّ مستقلّ عن بيئة المُولِّد (مثبَّت على هدف CI)

كان القفل حسّاساً لإصدار Python والمنصّة. عالجناه بتثبيت الحلّ في الأداة نفسها:
`--python-version 3.12` (دقّة CI = `ubuntu-24.04`/py3.12) و`--universal` (عابر
للمنصّات) — فيُنتِج المُولِّد المحلّيّ قفلاً مطابقاً بايتاً ببايت لإعادة الحلّ في CI،
بصرف النظر عن مُفسِّر/منصّة المُطوِّر. لذا يُولَّد القفل ويُلتزَم من أيّ بيئة فيها `uv`.

> ملاحظة: `--custom-compile-command` يُثبّت ترويسة القفل (`scripts/deps/lock.sh`)
> كي لا تُسرَّب مسارات `-o` المؤقّتة إليها، وإلّا أبلغ `--check` انجرافاً زائفاً.

## الاستخدام

```bash
scripts/deps/lock.sh          # يولّد <req>.lock بجانب كلّ هدف
scripts/deps/lock.sh --check  # يفشل إن انجرف قفل عن مصدره (بوّابة CI: Dependency Lock Drift)
```

الأهداف (المسار الحرج الذي تحجبه بوّابة `pip-audit` — انظر `CLAUDE.md`):
`services/sahool-platform/api/requirements.txt` ·
`services/auth/requirements.txt` · `services/guardrails-engine/requirements.txt` ·
`requirements_real.txt`.

## الحالة

- ✅ الأقفال مُولَّدة ومُلتزَمة (`*.lock` بجانب كلّ هدف، حلٌّ كامل عابر + تجزئات).
- ✅ بوّابة CI **Dependency Lock Drift** تشغّل `--check` فتمنع ترقية requirements دون
  إعادة توليد القفل (يبقى القفل مصدر حقيقة قابلاً للتدقيق).

## الخطوة المتبقّية (مؤجَّلة — تتطلّب بناء صور Docker للتحقّق)

تعديل `Dockerfile` لكلّ خدمة ليُثبّت من `requirements.lock` بـ`--require-hashes`
(بدل `requirements.txt`) فتصبح عمليّات البناء مقفولة فعليّاً. أُجِّلت لأنّ تثبيت
`--require-hashes` صارم ويجب التحقّق منه ببناء فعليّ للصور — لا يُشحَن دون ذلك تجنّباً
لكسر بناء الإنتاج. الأساس (أقفال مُدقَّقة + بوّابة انجراف) جاهز لهذه الخطوة.

> فرصة قيمة مكمّلة: تشغيل `pip-audit` على `*.lock` (الحلّ العابر الكامل) بدل
> `requirements.txt` (النطاقات الفضفاضة) يمنح تغطية ثغرات عابرة كاملة.
